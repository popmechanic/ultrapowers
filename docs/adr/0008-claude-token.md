# 0008. The Claude credential

Status: accepted (2026-11-21)  
Governs: `fleet/claude-token.mjs`

Recovered from the code comments removed by `/delete-comment` on 2026-11-21: each entry is a
decision the code cannot show on its own. Symbols are named; line numbers are not.

## Fleet token rotation

- **fleet/claude-token.mjs** — exe.dev has no account-linked Claude integration, its catalog anthropic object bills by API key, and an http-proxy bearer never refreshes itself, so fleet/claude-token.mjs owns the OAuth dance and refresh on the laptop while exe.dev injects the bearer at the edge. The keychain holds one item per account under service ultrapowers-claude-oauth; the access token lives only in the keychain and on stdin to 'integrations ... --bearer -', and the refresh token rotates on every refresh so the entry is rewritten each time. Metering (usage) rotates with install false and never installs, because installing another account's bearer would switch every live sandbox mid-run; refresh always installs the record's access token, even when fresh, because an earlier usage read may have rotated that account and left the edge on a revoked bearer (run-100, 2026-09-11). The flow and constants come from popmechanic/loom's OAuth reference.
- **REFRESH_AHEAD_MS** — fleet/claude-token.mjs rotates the access token at launch when fewer than four hours (REFRESH_AHEAD_MS) remain, because the token lives eight hours and nothing refreshes it mid-run; with a 30-minute window run-92 (2026-09-11) died with a 401 at minute 31. Four hours covers the longest recorded run (about 90 minutes) with margin, and a rotation is one cheap grant behind the single-flight lock.
- **LIVE_FLOOR_MS** — Because a refresh grant revokes the previous access token at once and the exe.dev edge carries one bearer for every run, fleet/claude-token.mjs holds rotation while any fleet VM is listed: with at least LIVE_FLOOR_MS (90 minutes, the longest run on record) left it installs the cached token and spends nothing; under it, refresh refuses outright. Runs 92, 100, 103 and 178 (2026-09-11 to 2026-09-17) were each killed by a rotation landing during a live run.
- **ACCOUNT_RE** — In fleet/claude-token.mjs an account name is both the keychain item's acct and a token in '--comment account=<name>' on an exe.dev lobby verb, so it must match ACCOUNT_RE and is checked before any keychain read, token request or lobby verb.
- **cleanCode** — The claude.ai OAuth callback page shows 'code#state'; cleanCode in fleet/claude-token.mjs keeps only the text before the first '#' as the authorization code.
- **codeForState** — codeForState in fleet/claude-token.mjs accepts a clipboard value only if it is exactly 'code#state' with this login's freshly minted state, so polling the clipboard can never exchange a stale value or someone else's code. Values with no '#', a different state, or more than one '#' are skipped and the poll waits on, because spending the login on an unvouched code is worse; cleanCode deliberately keeps the looser first-'#' split for the interactive path.
- **lobby** — fleet/claude-token.mjs passes the bearer to exe.dev lobby verbs on stdin ('--bearer -'), never in argv, so the token never appears in a process listing or ssh command line.
- **stdout** — fleet/claude-token.mjs writes machine-readable tables (accounts --json, usage) to stdout so other tools can parse them, and every human-facing line to stderr through log.
- **lock** — fleet/claude-token.mjs serializes refreshes across processes with a directory lock at ~/.ultrapowers/claude-token.lock, because two launches inside the refresh window would both refresh and the second would spend a refresh token the first already rotated away. mkdir is atomic on every filesystem; a lock older than LOCK_STALE_MS is taken as a dead process's. One lock covers every account; accounts serializing is acceptable.
- **installBearer** — installBearer in fleet/claude-token.mjs configures the exe.dev http-proxy integration with the bearer as the only injected header, because an injected header replaces the client's same-named one (measured 2026-09-03): injecting anthropic-beta would destroy Claude Code's own flags. The '--comment account=<name>' on the verb is what lets the doctor report which account the edge carries; the token itself rides stdin.
- **listLiveFleet** — listLiveFleet in fleet/claude-token.mjs counts every row with a vm_name from `ls 'fleet-*' --json` as a live run, ignoring status because the lobby's status vocabulary beyond running is not on record and the janitor already reaps finished runs' VMs. A listing that exits non-zero or is not JSON throws rather than reading as an empty fleet, since that would spend a grant that could kill a live run.
- **pollClipboardForCode** — login --code-from-clipboard in fleet/claude-token.mjs exists because the agent runs it from a Bash tool with no interactive stdin, so nobody can press Enter; pollClipboardForCode polls the clipboard and exchanges only a value carrying this login's state, which makes waiting safe.
- **refresh** — refresh in fleet/claude-token.mjs reads the keychain record only after taking the single-flight lock, so a launch queued behind a sibling's refresh sees the rotated pair and finds nothing to do.
- **refresh** — In fleet/claude-token.mjs a keychain record lacking accessToken (the shape from before usage metering) has nothing to install, so refresh rotates it as if it were inside the refresh window.
- **refresh** — When the record is fresh, refresh in fleet/claude-token.mjs spends no grant but still installs the access token at the edge, because another process (a usage read) may have rotated the token and left the edge carrying a revoked bearer.
- **refresh** — refresh in fleet/claude-token.mjs lists live fleet VMs before spending a refresh grant, because the grant revokes the previous access token immediately and the edge carries one bearer for all runs (runs 92, 100, 103, 178 died this way). Its 'not rotated' log and error lines are shared byte for byte with fleet/launch.mjs, which greps this tool's output for them, so their wording is a contract.
- **refresh** — refresh in fleet/claude-token.mjs writes the rotated token pair to the keychain before installing at the edge, because a consumed refresh token is dead and a crash between the steps must not leave the keychain holding it.
- **usageRow** — The /api/oauth/usage answer read by fleet/claude-token.mjs usageRow may omit five_hour or seven_day; a null or absent window means the account does not have that window, and a row is marked unread only when both are missing.
- **usage** — usage in fleet/claude-token.mjs reads accounts serially, not in parallel, because each row's rotation shares the single-flight lock; an unreadable row is still answered so no failure takes the table down.
- **main** — The CLI entry of fleet/claude-token.mjs calls process.exit after runCli resolves, so a login's clipboard poll or readline prompt cannot keep the process alive once main has answered.

## Fleet token keychain

- **parseKeychainDump** — parseKeychainDump in fleet/claude-token.mjs reads 'security dump-keychain' without -d, so no secrets are dumped: each item opens with a 'class:' line and carries '"acct"<blob>=' and '"svce"<blob>=' attribute lines in either order, so an item is judged only when it ends.
- **keychainList** — keychainList in fleet/claude-token.mjs enumerates accounts from 'security dump-keychain' without -d, so the dump carries account names and never secrets.
