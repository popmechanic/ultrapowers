# Deterministic census — fleet runs 24–32

Read straight off each run's `events.jsonl`, `gate-receipt.json` and worker
`envelope.json`s, not from a reader's judgment. Every number here is
reproducible from `.claude/ultrapowers/fleet-evidence-archive/sandbox-logs/`.
It exists because the sense pass over these runs rests on it, and because two
of its rows contradict things the project believed.

Runs 24–32 are **all** the One Driver engine. `engineVersion.epoch` stamps
24–27 as 0.2.25 only because they predate the 0.3.0 release commit — the stamp
is not the engine.

### What the five manual acks actually asked for

This is the row that corrects the record. The TDD-ordering diagnosis (#441)
covers **two** of the five, not all of them.

| run | the manual ack | class |
| --- | --- | --- |
| 28 | `git init -b main` needs git ≥ 2.28; the operator's host git version is not observable from the sandbox | **host fact** |
| 29 | RUNBOOK golden-image Bun steps, hand-executed against a live VM | **hand-executed record** |
| 29 | a `compile_plan.py --check` invocation printing PLAN OK | **hand-executed record** |
| 30 | RUNBOOK §Golden VM build — PEP 668 refusal, a 17 ms figure, a 535M figure, tag inheritance | **hand-executed record** |
| 31 | red-first evidence for all three tasks | **TDD ordering** (#441) |
| 32 | TDD red-state evidence for all six task suites | **TDD ordering** (#441) |

So the shipped #441 repair closes runs 31–32's class. Runs 28–30 parked on a
**different and larger** class: *claims about the world outside the repository*
— a host's git version, a document hand-executed against a live VM. No sandbox
can ever verify those, and no reviewer prompt edit will change that.

## Retries and ghost attempts

**Zero.** Across all nine runs there is not one duplicated worker label, not one
`worker:end` with a non-success class, and not one of the 36 reviews returned
under 500 output tokens. #264's trigger (ghost review attempts above ~25% of
reviews) does not fire — but the retry machinery itself changed at the cutover,
so read this as *deleted, not fixed* unless someone shows otherwise.

## The denial ledger under-reports, mechanically

`confine-denials.jsonl` records only what the `PreToolUse` hook refused. The
worker envelopes record every permission denial the worker actually hit.

| run | `confineDenials` | envelope denials |
| --- | --- | --- |
| 26 | 0 | 3 |
| 28 | 3 | 11 |
| 30 | 2 | 11 |
| 31 | 1 | 11 |
| 32 | 3 | **20** |

The friction lens was reading between a fifth and a tenth of the truth. #471
made the envelope copy visible to a reader; the ledger itself is still wrong.

Of the 11 post-cutover hook denials, **6 are static-parse artifacts** rather than
boundary violations — a bare backtick, `$n`, `/*/`, and a path inside a
backticked expression. The hook refuses what it cannot parse, and says the
worker tried to escape.
