## Problem

Three successor modes to #126 (whose target mode held — zero recurrence),
each at the 2–3-run recurrence bar, each corrupting a statistic distills
rank on: (a) crash-resume runs double-count audits (~7.48M-token headline
overstated by a full salvage run's weight); (b) slices always truncate
before the operator's approval exchange, blinding the NEEDS_ACK audit;
(c) clean drain-administered runs read as terminus `unknown`, feeding
"unresolved" statistics.

## Design

### (a) Audit dedupe — one layer, at the dir level

Grounded: `_transcript_dirs` collects every printed "Transcript dir:" with
no dedupe (harvest_runs.py:315–336) and `_merge_audits` bare-extends agents
across dirs (:494–496). Both observed failure signatures (the ~50-entry
block duplicated back-to-back; the 18-entry block repeated verbatim) are
the same transcript dir audited twice.

Fix: **`_transcript_dirs` dedupes candidates on their resolved real
paths** — each unique dir is audited once. That alone makes the verbatim
duplication inexpressible, and `_merge_audits`' existing key-wise summing
over unique audits stays correct with no recompute machinery.

Rev 1's additional layers — a `transcript` identity field in audit_run.py
plus per-entry dedupe keyed on it — defended an *overlapping-dirs* variant
with no cited recurrence (below the 2–3-run bar) and are **deleted**:
audit_run.py stays untouched, the surface shrinks to harvest_runs.py
exactly as the issue stated. If the overlapping-dirs variant ever shows up
in a batch, it files with its own evidence.

### (b) Slice through the approval exchange

Grounded: `_last_artifact_record_index` cuts at the last qualifying
artifact (harvest_runs.py:123–152; drop at :164–166), so the approval
exchange — plain user text after the final artifact — is structurally
excluded. Rule: **when the bundle's terminus is `approved`, the slice
extends past the artifact cut to the transcript end.** The extension passes
through the existing `SLICE_KEYWORDS` filter unchanged (:175) — operator
user-text survives it, tool noise is filtered exactly as everywhere else,
and since approval is terminal the filtered tail is naturally a handful of
records. Rev 1's 80-record cap and `[slice truncated at cap]` sentinel are
**deleted** (an ungrounded constant plus a marker with no named consumer —
trim-review catch). Non-approved termini keep today's cut.

### (c) Drain-administered gate terminus

Grounded: gate-receipt.json is written ONLY by frozen ultra_gate.py (:249),
and the drain skips Step-5 by design (ultradocket SKILL.md:132–133) — so
drain-gated runs have no receipt to read. Fix, mirroring AROUND the frozen
files, never in them:

- **`record_wf_run.py` gains a `stamp` subcommand** (no new script — it is
  already the drain's "write a durable record keyed by stamp under
  `.claude/ultrapowers/`" helper, same audience, same SKILL step region):
  `record_wf_run.py stamp <stamp> <entry> --verdict <v> --exit-code <n>
  --branch <b> --base <ref>` writes
  `<repo-root>/.claude/ultrapowers/receipts/<stamp>-<entry>.json`
  (gitignored, teardown-surviving). **Mirror-only — no runDir copy** (rev
  1's dual write had a location nothing reads; the motivating 0.1.15 mode
  is precisely a deleted runDir).
  - **Schema authority is the writer**: the harvest-side test consumes a
    fixture generated by invoking the writer, so writer and reader cannot
    drift apart silently.
  - **Re-gates overwrite**: same stamp + entry after a fix round replaces
    the file — last write wins; the final verdict is the record.
  - **Scope: waves-engine entries only**, stated in the SKILL step —
    subagent/inline entries have no engine runDir or registry stamp, so
    the harvester could never consume their stamps.
- `skills/ultradocket/SKILL.md` step 3: record the stamp right after each
  drain-administered `run_acceptance.sh`, alongside the existing
  `record_wf_run.py` call.
- `harvest_runs.py` terminus derivation: a drain stamp is gate evidence —
  the receipt-present path generalizes to "receipt-or-stamp present," with
  the same approved-upgrade logic. **Mirror discovery is path-string
  derivation**: the registry's recorded runDir path yields the repo root by
  stripping the `.claude/ultrapowers/run-*` suffix — no filesystem access
  to the (possibly deleted) runDir is needed; lookup is the
  `<stamp>-*.json` glob under `<repo-root>/.claude/ultrapowers/receipts/`.

### What does NOT change

- Frozen files byte-identical: run_acceptance.sh, ultra_gate.py,
  gate_check.py. Verdict authority remains the gate's exit code.
- audit_run.py: untouched (rev 2).
- Harvester stays advisory/soft-fail; no engine (waves.js) surface → no
  sims, no re-bake.
- Mode (a) is independent — it ships even if (b)/(c) need another pass.
