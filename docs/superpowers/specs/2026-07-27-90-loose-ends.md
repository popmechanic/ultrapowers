# Spec: loose ends from the #90 build — drainable items 1–4 (#95)

**Status:** approved design — brainstormed 2026-07-27 (docket sweep iteration 6).
Surfaces: `skills/ultrapowers/scripts/compile_plan.py` + `tests/test_plan_check.py`,
`tests/test_ultra_run.py`, `tests/sim_workflow.mjs`, `skills/ultrapowers/SKILL.md`.
None are the frozen verification periphery.

## Problem

The #90 build's redirect-round reviewers flagged four cheap hardening gaps
(run `20260727-114316`, merged at `6229ebc`). None blocking; bundled so they
don't evaporate. The issue's three live-run verification checkboxes are
**explicitly out of scope** — they close only by observing the first real
`/ultrapowers` run after 0.1.12 re-resolves, and the issue stays open for
them after these items land.

## Design

Four independent fixes with disjoint files.

### 1. `--check` help parity + missing rejection test

The runtime rejects `--check` combined with any of
`--emit-launch`/`--emit-args`/`--run-dir`, but the `--check` argparse help
still reads "Mutually exclusive with --emit-launch/--emit-args." — the
documented and enforced contracts drifted. Fix the help string to name all
three. The `--run-dir` arm of the rejection is untested (the emit arm has
`test_check_is_exclusive_with_emit`): add the matching case to
`tests/test_plan_check.py` (the pinned CLI-contract surface) asserting
`--check --run-dir X` exits non-zero with the mutual-exclusion error.

### 2. Prune honest-receipt failure branch gets tests (test-only)

`prune_run_dirs`'s post-check filter (`if not d.exists()`) and the
`"; N removal failed: …"` scratch-hygiene detail are only exercised on the
all-succeed path, where they are indistinguishable from the old dishonest
"report the doomed list" behavior — a regression reverting to
`[d.name for d in doomed]` would pass the whole suite. Two tests in
`tests/test_ultra_run.py`:

- **Return honesty (unit):** monkeypatch `ultra_run.shutil.rmtree` to a
  no-op, seed three `run-<stamp>` dirs, call `prune_run_dirs(state, keep=1)`
  → the return is empty (nothing actually vanished), never the doomed names.
- **Receipt detail (driver-level):** seed `KEEP_RUNS + 1` run dirs in the
  fixture repo's state dir, make the single doomed one undeletable (a child
  file plus `chmod 0o500` on the dir — rmtree cannot unlink the child, and
  `ignore_errors=True` swallows it), run the driver, assert the
  `scratch-hygiene` stage detail contains `removal failed` and the doomed
  dir's name, while the run itself stays green. Restore the mode at test end
  so tmp_path cleanup works.

### 3. Sim `engineAuthoredSpan` guard: subtract plan-authored blocks

The guard truncates the checked span at the FIRST of `\nTASK:` /
`\nGLOBAL CONSTRAINTS:` / `\nINTERFACES:`, so engine-authored text appended
AFTER the plan-authored blocks — the FIX ROUND preamble the harness splices
into the task-body region on fix rounds — escapes the
no-unsubstituted-placeholder assertion. The #90 reviewer proved it: a
literal `<runDir>` inserted into the FIX ROUND string in a shadow copy
still yielded `ALL SCENARIOS PASSED`. No live defect (the FIX ROUND text
carries no tokens today) — a weakened guard.

Fix in `tests/sim_workflow.mjs`: derive the engine-authored span by
**subtracting the known plan-authored literals** instead of truncating. A
module-level registry (`planAuthoredTexts`, default empty) that a scenario
sets to its fixture's plan-authored strings; `engineAuthoredSpan(prompt)`
removes every registered literal and returns the remainder, so the
placeholder guard covers ALL engine-authored text wherever it sits in the
prompt. Scenarios that quote no tokens in plan prose leave the registry
empty and get a strictly wider guard for free. Add an inline self-test
proving the old blind spot is closed: with the fixture literals registered,
a prompt carrying `<runDir>` in engine text placed AFTER the `\nTASK:`
block must still be caught by the guard.

Harness-sim discipline: the sim keeps its `ALL SCENARIOS PASSED` success
sentinel. This change touches only the sim, not `harnesses/*.js`, so the
suite-gate will not run it for this branch — the plan verifies it manually
via `node tests/sim_workflow.mjs`.

### 4. SKILL.md Salvage/Redirect relaunch-args line

The harness refuses to launch without `pluginRoot`/`runDir`; a hand-authored
relaunch that reconstructs args from the report would throw. Add one
sentence to the Step-5 Salvage and Redirect bullets: compose the relaunch
`args` by spreading the receipt's argsFile (which carries the mandatory
`pluginRoot`/`runDir`), overriding only `waves`/`resume`/bodies as the
bullet directs — never rebuild args from the report.

## Testing

Items 1–2 are (or include) their own pytest coverage; item 3 is verified by
running the sim (`node tests/sim_workflow.mjs` → `ALL SCENARIOS PASSED`,
including the new self-test); item 4 is prose. Suite gate:
`python3 -m pytest` green.

## Rejected alternatives

- **Prose-pinning the help text** (asserting the exact help string): the
  behavioral rejection test plus the corrected string gives parity without
  a brittle prose pin.
- **Structural FIX-ROUND-marker parsing** for item 3 (treating
  `\n\nFIX ROUND` as an engine-span resumption marker): couples the guard
  to every future engine-authored insertion point; subtraction of known
  plan literals covers all of them by construction.
