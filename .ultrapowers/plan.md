# The publish re-fold's resolver runs under the engine's own environment, and a dispatch that ends in an error writes the error on its row

**Grammar:** claims-v1

**Claim:** A re-fold's resolver runs under the same environment as the engine unit, and a dispatch that ends in an error writes it: `dispatch:end` carries `error: <first 500 chars>` so a resolver that never ran is a fact on the record, not a 642 ms gap. (quoted from #1207)
**Summary:** This makes the resolver that settles a same-file overlap at publish actually run, and makes any worker that dies before it starts say why on the run's own record. It exists because run-207 folded three of three tasks green and then parked on a one-hunk overlap that git merges clean: the resolver was dispatched and gone in 642 milliseconds with no reason recorded (n=1 run, run-207, 2026-09-21), and the boot had started it without the base URL and the token the engine unit gets. After it, two concurrent runs that touch one region are joined in the kernel rather than by hand on GitHub, and the next such gap on the record carries the error text instead of silence; the rollback is the parked-run path by hand, as tonight.

**Goal:** #1207: `factory/engine.mjs`'s `--refold` entry builds its `dispatch` through one exported pure function, `makeRefoldDispatch({ worker, appendEvent })`, whose `dispatch:end` row carries `error` — the first 500 characters of a worker's thrown message, `null` otherwise — and `factory/boot.sh`'s `refold_onto` starts that entry under the same `env -u CLAUDE_CONFIG_DIR ANTHROPIC_BASE_URL=… TYPESAFE_BASE_URL=… CLAUDE_CODE_OAUTH_TOKEN=placeholder ULTRAPOWERS_FLEET_RUN=…` line the engine unit gets, with `fleet/CONTRACT.md` saying so. The pre-registered reading — publish re-folds that met a conflict, and of those how many the resolver settled (`refold ok=true` after a `resolve:refold:*` dispatch) — is read off the rows the boot and the engine already write; no census script is added.
**Closes:** #1207

**Tech Stack:** Node 24 ESM for the factory and its exam, bash for the boot, markdown for the contract. No new npm dependency.
Spec: none on disk — issue #1207 is the brief, and everything a worker needs is in its task's Context. The sandbox holds no spec.

## Global Constraints

- Check: git diff --quiet $ULTRA_BASE -- factory/roles factory/board.mjs factory/union.mjs factory/worker.mjs factory/reverify.mjs fleet/fleet-bootstrap.sh skills/ultrapowers/kernel
- A row carries its keys: no exam of this plan pins the exact key set of an `events.jsonl` row, because the engine's writer adds `ts` and a sibling plan may add more.
- The re-fold's answer and exits are unchanged: `main` still prints one JSON object — `{ refolded, head, onto }` or `{ refolded: false, reason, … }` — and exits 0, 3 or 4 as it does today; nothing of this plan changes what the boot reads off that line.
- No credential in any argv: the token stays the literal `placeholder` and the edge injects the bearer; no `ANTHROPIC_API_KEY`, no `anthropic` SDK, no direct API call.

### Task 1: The re-fold's dispatch writes a worker's error on its dispatch:end row

**Type:** implementation
**Review:** peer

**Files:**
- Modify: `factory/engine.mjs`
- Test: `fleet/tests/test_factory_refold_dispatch.mjs`

**Claim:** a dispatch that ends in an error writes it: `dispatch:end` carries `error: <first 500 chars>` so a resolver that never ran is a fact on the record, not a 642 ms gap (quoted from #1207)
Machine: M1. `factory/engine.mjs` exports `makeRefoldDispatch({ worker, appendEvent })`, answering an async `dispatch(opts)`. When `worker` rejects, the call resolves an object whose `result` is `null`, whose `denials` is an empty array and whose `error` is the first 500 characters of the rejection's `message` — of its string form when it has no `message` — and `appendEvent` received exactly two rows, in order: one whose `kind` is `dispatch:start` carrying `task`, `label` and `role` off `opts`, then one whose `kind` is `dispatch:end` carrying `task`, `label` and `role` off `opts` and `error` equal to that same string. The call never rejects.
M2. When `worker` resolves, the call resolves exactly the object the worker answered; the `dispatch:end` row's `error` is exactly `null`; `worker` was called exactly once, with an argument whose `cwd`, `prompt`, `systemPrompt`, `model`, `files`, `role`, `label` come off `opts` as given, whose `task` is `opts.taskId`, whose `readOnly` is `true` when `opts.readOnly` is `true`, whose `schema` is `opts.schema` — `null` when none was given — and whose `onDenied` is a function that appends the row it is handed through `appendEvent`.
M3. `runRefold` builds its `dispatch` through `makeRefoldDispatch(`, handing it its own `worker` and `appendEvent`.

**Authorized-by:** #1207 (desired state: "One exam: the `--refold` entry's dispatch, given a worker that throws, appends a `dispatch:end` row carrying the error text"); map #1131.

**Context:** You see this task body and nothing else. **Why:** on run-207 (n=1 run, 2026-09-21) the publish re-fold met one overlap — one hunk of one file, a shape git merges clean — and dispatched a resolver; the record shows `dispatch:start` and `dispatch:end` for `resolve:refold:1` 642 ms apart with no `worker:*` row between them, then `refold:conflict`. The worker had thrown before its first turn, and the reason went nowhere: the `--refold` entry's own `dispatch` folds the error into the answer and writes a bare `dispatch:end`. **What exists at BASE** in `factory/engine.mjs` (2,431 lines): `runRefold(rawArgs, deps)` (about line 2160) takes `worker`, `sh`, `git`, `log`, `judge`, `readUnion` and `ask` off `deps` (`deps.worker || runWorker`), defines its own `appendEvent` (about line 2180: `fs.appendFileSync(eventsPath, JSON.stringify({ ts: new Date().toISOString(), ...row }) + '\n')`), and about lines 2206–2224 defines `const dispatch = async (opts) => { … }` — it appends `{ kind: 'dispatch:start', task: opts.taskId, label: opts.label, role: opts.role }`, awaits `worker({ cwd: opts.cwd, prompt: opts.prompt, systemPrompt: opts.systemPrompt, model: opts.model, files: opts.files, schema: opts.schema ?? null, mcpServers: opts.mcpServers ?? null, onMessage: () => {}, readOnly: Boolean(opts.readOnly), role: opts.role, label: opts.label, task: opts.taskId, onDenied: (row) => appendEvent(row) })`, on a throw sets `answer = { result: null, denials: [], error: String((e && e.message) || e).slice(0, 500) }`, then appends `{ kind: 'dispatch:end', task: opts.taskId, label: opts.label, role: opts.role }` — no `error` — and returns `answer`.
