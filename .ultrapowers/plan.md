# The fold record rides the evidence tag — the boot copies `frontier/` beside the receipts, and a census reads conflicts by shape off it

**Grammar:** claims-v1

**Claim:** `collect_evidence` copies `frontier/` (fold logs, conflicts index, narrations, briefs, replies) into `.ultrapowers/runs/<N>/frontier/` beside the receipts, sized (briefs and replies are small text); the boot writes `publish:pr`, `publish:hold` and `publish:merge` events per #703; `census.py` reads the fold logs and emits per run: conflicts narrated, by shape (insert-only at one anchor / deletion-only / overlapping modification / binary), resolver dispatches, retries (quoted from #728)
**Summary:** Today the record of how a run's edits were folded together — which files collided, what shape each collision took, and how many times a resolver was asked to settle one — is written on the sandbox and dies with it, so nobody can say whether the collisions we pay resolvers for are the trivial kind or the hard kind. After this, every run's fold record is copied onto its evidence tag beside the receipts, bounded so a runaway file can never swamp the record, and a census reads those copies back as one row per run: conflicts by shape, resolver dispatches, retries and how many were settled. That row is what lets the resolver policy be decided on a count rather than a story, and it is read from the tag long after the sandbox is gone.

### Task 2: A census reads conflicts by shape, dispatches and retries off the copied fold record

**Type:** implementation
**Review:** peer

- Test: `tests/test_fold_census.py`

**Claim:** I point one script at a run's evidence directory and read one row for that run: how many conflicts its folds narrated, how many were insert-only, deletion-only, overlapping or binary, how many parked, how many resolvers were dispatched, how many of those were retries, and how many conflicts were settled. (derived)
Machine: M1. `python3 skills/ultrapowers/scripts/fold_census.py <run-dir>...` reads, under each run directory, every `frontier/wave-<n>/` (wave named `<n>`) and every `publish-fold/frontier/wave-<a>/` (wave named `publish-<a>`), and prints to stdout a header whose whitespace-separated fields are exactly `run`, `waves`, `conflicts`, `insert-only`, `deletion-only`, `overlapping`, `binary`, `parked`, `dispatches`, `retries`, `resolved`, in that order, then one row per run directory in argv order whose first field is the directory's basename and whose remaining ten are that run's counts. M2. A conflict is one entry of a wave's `conflicts.json`, and its shape is: `binary` when the entry's `kind` is `binary`; `deletion-only` when its `kind` is `delete/modify`; otherwise, from the marker lines of `conflict-<i>.txt` — every line starting `<<<<<<< begin ` or `======= begin `, whose next word is the segment kind — `insert-only` when every segment kind is `added`, `deletion-only` when every one is `deleted`, `overlapping` when both occur, and `unclassified` when the file is missing, unreadable or carries no marker line; `conflicts` counts every entry and the four shape columns count only their own, so an `unclassified` entry is in `conflicts` and in none of the four. M3. Per wave, `dispatches` is the number of `reply-<i>-<attempt>/` directories, `retries` the number of those whose `<attempt>` is 2 or more, `parked` the number of entries whose `dispatchable` is false, and `resolved` the number of entries whose `path` carries, in that wave's `fold_log.jsonl`, a `{"type":"resolve"}` row with `epoch` greater than or equal to the entry's `epoch`; the run's counts are the sums over its waves. M4. `--json` prints instead one JSON object per run directory per line, keys exactly `run`, `waves` and `totals`: `waves` a list of `{"wave", "conflicts"}` in wave order, each conflict an object with keys exactly `i`, `path`, `kind`, `shape`, `anchors` (the number of `>>>>>>> end conflict` lines in its narration, 0 when unclassified), `dispatchable`, `autoResolved`, `hunkCount`, `dispatches`, `retries`, `resolved`; `totals` an object whose keys are the ten count columns of the table. M5. A run directory with neither `frontier/` nor `publish-fold/frontier/` prints a row of zeros (`waves` 0) and exits 0; a wave whose `conflicts.json` is missing or is not a JSON list is counted in `waves`, contributes no conflict, and prints one stderr line naming that file; the exit code is 0 whenever every argument is a directory and 2 when one is not, with that argument named on stderr and no row printed for it.
