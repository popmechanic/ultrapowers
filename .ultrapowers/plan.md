# Split the engine along its seams: measure, fold, refold

**Grammar:** claims-v1

**Claim:** After this run, the engine's measuring, its folding and its re-folding each live in a file of their own, a re-fold goes through the same fold a task's landing goes through, and every run and every re-fold behaves exactly as it did before. (elicited)
**Summary:** This splits the factory's one very long engine file into three smaller files, one each for measuring a candidate, folding a landing into the run, and re-folding a finished run onto a main that moved. The re-fold today carries its own copy of the merge step, which has already drifted from the landing's copy twice — once in how it calls the merge kernel and again in how it passes the new fold setting — and one copy cannot drift from itself. Nothing a run does changes; the next fix in any of these three places is made in one short file instead of inside a 2,400-line one.

**Goal:** Move `measure`/`scoreOf`/`postLanding`/`candidatesOf`/`excerptTests` into `factory/measure.mjs`, `foldIn`/`resolveConflicts`/`runProofsAndChecks`/`reverifyAfterFold`/`makeCloner` and the one kernel wrapper into `factory/fold.mjs`, and `runRefold`/`makeRefoldDispatch` into `factory/refold.mjs`, where `runRefold` becomes one `foldOnto` plus one `runProofsAndChecks` over `fold.mjs` instead of its own kernel wrapper, fold loop and verify loop; `factory/engine.mjs` re-exports every symbol a sim imports from it today.
**Closes:** #1276

**Tech Stack:** Node 24 ES modules (`factory/`), the fold kernel `skills/ultrapowers/kernel/fold_wave.py` (unchanged). The suite: `python3 -m pytest -q` from the repository root, which bridges every `fleet/tests/test_*.mjs`.

Spec: popmechanic/ultrapowers#1276 (structural proposal 1 of the 2026-09-24 whole-codebase review).

`makeKernel({ sh, log, policy })` answers the one kernel wrapper: it runs `python3 <KERNEL> ...argv` through `sh` with cwd the repository root, parses the last JSON object of stdout (`lastJson`), logs `kernel <argv[0]>: exit <n> <stderr tail>` when there is none, and — exactly as #1278 made both BASE wrappers do — puts `ULTRA_FOLD_FULL_CHECKS=1` into the kernel's environment whenever `((policy.fold || {}).single_task_fast || {}).enabled === false`. `runProofsAndChecks(ctx, opts)` is the BASE function with its closed-over state (`sh`, `appendEvent`, the selected tests per task, `selectPolicy.timeout_seconds`, `proofsEnabled`, the plan's `checks`, `runBase`, `proofTimeoutSeconds`) passed in `ctx`; `includeChecks` still defaults to `true`, and every `check:line` row and every red keeps its BASE shape.
