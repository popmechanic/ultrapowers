# A launch never renews the Claude sign-in under a live run — it starts on the current one and says so, or declines naming the runs — and a relative plan path is read from --repo

**Grammar:** claims-v1

**Claim:** When I launch a plan while other runs are still going, the launch never kills them: it either starts on the sign-in they are already using and says so on the launch line, or it declines in one line that names the live runs and when the sign-in runs out; and a plan path I give relative to the target's folder is read from that folder. (elicited)
**Summary:** This makes the sign-in step of a launch — and the same step run by hand or by a usage reading — decline to renew the Claude sign-in while any fleet machine is up, and it makes the launcher read a plan path from the target's folder, as the written steps already say it does. It exists because renewing the sign-in cancels the one every live run is using — run-178 died that way when another session launched, the same class as runs 92, 100 and 103 (n=4 runs, 2026-09-11 to 2026-09-17) — and because a first-time operator following the written steps met a file-not-found on fixture run-36 (n=1 launch, 2026-09-21). After it a launch beside live runs starts on the current sign-in when that has at least ninety minutes left and says so, or declines in one line naming the live machines and the expiry, so no run is lost to somebody else's launch.

**Goal:** #1113: `fleet/claude-token.mjs`'s `refresh` lists the fleet before any grant and never rotates while a `fleet-r*` VM is listed — it holds on the cached bearer at ninety minutes or more, and refuses under that — so the launcher, a hand `refresh --force` and a `usage` read all meet one rule; `fleet/launch.mjs` carries the hold onto the launch line and turns the refusal into a one-line `Refusal` before anything is pushed; `CLAUDE.md` and `fleet/RUNBOOK.md` stop calling the launcher's in-window refresh safe. #1188: the launcher resolves a relative plan path against `--repo`.
**Closes:** #1113 #1188

**Tech Stack:** Node 24 ESM, no new npm dependency; Markdown.
Spec: none on disk — issues #1113 and #1188 are the brief, and everything a worker needs is in its task's Context. The sandbox holds no spec.
