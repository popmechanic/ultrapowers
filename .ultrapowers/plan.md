# The launcher refuses a Publish plan whose target uploads assets

**Grammar:** claims-v1
**Claim:** The launcher refuses a `**Publish:**` plan whose target deploys static assets through the edge, before any VM exists. (quoted from #1313)
**Summary:** This stops a publishing plan from launching when its app is set up to upload its page files separately, a deploy the fleet's network edge always rejects. It exists because the Run Room run built, checked and merged all twelve of its tasks and then failed at the very last step, spending the whole run on a deploy that could never succeed. You find out on your laptop in a second, with a line pointing at the fix, instead of after a full run.

**Goal:** Before anything is pushed and before the pool is read, the launcher reads the target's `wrangler.jsonc` at `--base` and refuses a plan carrying `**Publish:**` when that config declares `assets`, naming #1312 and the pack step.
**Closes:** #1313
**Tech Stack:** Node 22 ESM; the launcher's exec seam and `fleet/tests/_lobby_helpers.mjs` (no network in any probe).
Spec: #1313; why: #1312.

## Global Constraints

- The refusal comes before any mutation: no plan branch pushed, no lobby verb issued, no kata filing.
- No new test file is written; the probes below are the proof.
- Check: python3 -m pytest -q tests/test_fleet_suite.py -k launch

### Task 1: A Publish plan against an assets config is refused on the laptop

**Type:** implementation

**Files:**
- Modify: `fleet/launch.mjs`

**Claim:** The launcher refuses a `**Publish:**` plan whose target deploys static assets through the edge, before any VM exists. (quoted from #1313)
Machine: M1. A launch whose parse carries a `publish` object, against a target whose tree at `--base` holds `server/wrangler.jsonc` whose top-level object (with `//` comment lines) carries an `assets` key, throws a `Refusal` with exit code 2 whose message is one line naming `server/wrangler.jsonc`, `#1312` and the `pack` step, and records no `git push`, no `ssh exe.dev new` and no `ssh exe.dev billing` call. M2. The same launch against a `server/wrangler.jsonc` with no `assets` key is not refused this way: it reaches the pool read, where the probe's pool of `max_cpus 0` refuses it. M3. A launch whose parse carries `publish: null`, against the target whose config declares `assets`, likewise reaches the pool read.

**Authorized-by:** #1313 (desired state: the launch compiles as today; with `**Publish:**` and `assets` in the target's `wrangler.jsonc` at `--base` it refuses on the laptop with one line naming #1312 and the pack step; nothing pushed, no VM)

**Interfaces:**
- Consumes: none
- Produces: none

**Context:** Why: exe.dev's edge replaces `Authorization` unconditionally, so wrangler's asset-upload JWT is refused 401 (#1312); popmechanic/runroom run-1 (2026-09-26) merged all 12 tasks and then died in `publish:deploy`. The fix on the target side is #1312's pack step: the client build is packed into the Worker and `assets` leaves the config. Where: in `launchBody`, right after the existing `publishRefusal` check and before `toolchainViolations`, the pool read, the credential and the push. The parse is `firstCompiled`; `plan_parse.py` prints the Publish line as `publish: {deploy, verify, rollback}`, which `compilePlanForRun` (`fleet/compiler.mjs`) leaves at `firstCompiled.payload.publish` — note `firstCompiled.publish` is never set, so read the payload's key. How to read the target: the base is already a commit in `repoDir`, so use the launcher's `git(exec, repoDir, argv)` from `fleet/lobby.mjs` through the exec seam — `ls-tree -r --name-only <base>` for every path whose basename is `wrangler.jsonc` (runroom's is `server/wrangler.jsonc`), then `show <base>:<path>`. The file is JSONC: runroom's carries `//` comment lines and a `"$schema": "node_modules/wrangler/config-schema.json"` string, so strip comments without touching string contents before `JSON.parse`, and test for a top-level `assets` key. A wording such as `launch: the plan carries a **Publish:** line but server/wrangler.jsonc at --base declares assets, and the edge refuses wrangler's asset upload (#1312) — add the pack step that serves the page from the Worker and drop assets; no VM was created and nothing was pushed` fits. Leave `publishRefusal` as it is. The check retires with #1312: once the pack step is the TinyApp default, no conforming target declares `assets`.
