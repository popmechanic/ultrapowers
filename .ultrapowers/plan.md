# The early baseline — a red repository parks the run before a worker spends a token

**Grammar:** claims-v1

**Claim:** A run whose repository was already failing before it started stops in minutes, before any worker spends a token, and its status page names the failing tests. (elicited)

**Goal:** Close #862 in its widened, operator-approved shape: the engine starts the BASE suite on a clone of its own the moment Setup ends, concurrently with wave 1 and off the critical path; the result is a fact in the record (`baseline: green | RED on <sha>`, `report.baseline`); a red baseline parks the run at once — before any implementer is dispatched if it settles first, at the wave barrier otherwise — with no reconcile ever dispatched for a red BASE already carries, and the parked status page's `error` cell names the failing tests. A green baseline makes every later candidate red attributable to the wave. One baseline pass per run, never two.
**Closes:** #862

**Tech Stack:** Node 24 ESM (`fleet/run-engine.mjs`, `fleet/tests/*.mjs` sims bridged into pytest by `tests/test_fleet_suite.py`), bash (`fleet/sandbox-boot.sh`), markdown (`fleet/CONTRACT.md`, `skills/ultrapowers/references/report-format.md`).

**Spec:** none — the authority is issue #862's "Widened 2026-09-09 (operator-approved shape)" comment, quoted in Context below.

**Parallelization rationale:** one wave of width 1. The engine change, the pins it owns in three existing sims, the report-format rows, the boot script's one parked line and the contract clause are one seam — every one of them pins the same behaviour, and a split would leave a wave-1 folded tree red (the lazy-baseline pins in `test_run_engine_baseline.mjs` and `test_run_engine.mjs` fail the moment the baseline runs eagerly). The plan is linear because it is one task.

**Claim:** A run whose repository was already failing before it started parks at wave 1's barrier at the latest — before any implementer is dispatched when the baseline settles first — never reconciles the red it inherited, and its status page names the failing tests. (derived)
Machine: M1. The engine starts the run's suite command on BASE's tree in a clone of its own, `<runDir>/clones/baseline` (cut at BASE, bootstrapped when `bootstrapCmd` is set, a directory that is neither `clones/integration` nor any `clones/task-<id>`), during Setup and does not wait for it before dispatching wave 1: with a suite that takes at least 2 s on BASE, the wall-clock timestamp at which wave 1's first `impl:` agent is called precedes the timestamp at which that baseline suite command finishes.
M2. When BASE's suite is red, the run parks without a reconcile: no agent whose label starts `reconcile:` is ever called; `report.baseline` is `{ passed: false, output }` where `output` contains the failing test's own line; one `engine:log` line is exactly `baseline: RED on <baseSha>`; `report.waveMerges[0]` has `status` `TEST_FAILED` and a `detail` that begins `baseline: the suite is RED on BASE`; every later wave is `SKIPPED`; and the integration branch `ultra/integration-<stamp>` still resolves to BASE.
M3. When BASE's suite has already settled red before wave 1's first chunk is dispatched, no agent whose label starts `impl:` is called at all; when it settles red only after implementers were dispatched, the park happens at the wave barrier and M2 holds unchanged.
M4. When BASE's suite is green and a wave's folded candidate is red, exactly one agent labelled `reconcile:wave1:1` is called, `report.baseline.passed` is `true`, and the wave ends `MERGED` when that reconcile reports `FIXED` — as at BASE.
M5. The suite runs on BASE's tree exactly once per run — on an all-green run, on a red-candidate run and on a run with two red waves alike — and every execution on BASE's tree happens in `clones/baseline`, never in `clones/integration`; `report.baseline` is never `null` after Setup completed.
M6. After the boot script parks a run whose branch has no commits ahead of base, `status.json.error` still begins `parked: <branch> has no commits ahead of base (verdict <verdict>)` and, when `<run dir>/acceptance.log` exists and carries a failure line, continues with ` — ` and the failing test's own block cut from that file; when the file is absent the cell is exactly BASE's sentence.
