# A task whose state exam killed its mutant gets no reviewer, and the role files say so

**Grammar:** claims-v1

**Claim:** A task whose state exam killed its mutant gets no reviewer, and the role files say so. (elicited)
**Summary:** This stops paying a reviewer to re-read a task whose own state exam already proved it would catch a wrong answer: when the planted fault was caught, the driver's proofs and checks still gate the task, the fold and the pre-merge gate still run, only the reviewer's second reading is skipped, and the two sentences that told the examiner and the reviewer to hunt for hollow exams by hand come out of the role files, since the planted fault is that hunt. It is an experiment at n=0, recorded on #836: the reviewer was 12 to 20 percent of judging spend on the last three fixture runs, and this is the one lever that spend can move without touching what gates a merge. It is read as escapes and judging share over the next three TinyApp runs against the 63/59/65 percent judging baseline of runs 13, 12 and 16, and the rollback is one switch, reviewOnStateExams back to on, which restores the reviewer on every task.

**Goal:** #836 (the two reviewer/examiner sentences the state-exam mutant retires, and its 2026-09-16 reading: reviewer 12–20 % of judging spend, examiner 40–45 %, n=3 merged fixture runs 13/12/16): an engine switch `reviewOnStateExams`, default off, under which a task whose pre-review pass is green and whose state-exam record shows every mutant killed dispatches no reviewer and is merged on the driver's own evidence with `reviewVerdict: skipped-mutant-killed`; the rollback is `reviewOnStateExams: true`, which restores BASE's one reviewer per task byte for byte; the examiner's "one that would pass against a stub" clause and the reviewer's duty-5 "still passes with the behavior it names deleted" sentence come out of `fleet/roles/`; and the pull request card's `mutant` cell says `killed, reviewer skipped` on such a row, so an operator reading the PR sees which tasks no reviewer read. #836 stays open as the experiment's record.

**Tech Stack:** Node ESM engine under `fleet/` (`run-engine.mjs`, the review round inside `runTaskInner`; args read the way `foldAgeMs` is, #1006), engine sims under `fleet/tests/test_run_engine_*.mjs` driven through `rig()` of `fleet/tests/_engine_helpers.mjs` (real git, real clones, real fold, only `agent` canned); the sandbox boot `fleet/sandbox-boot.sh` (its PR card is an inline python program) with boot sims driven through `fleet/tests/_sandbox_boot_helpers.mjs` (`makeHome`, `bootAsync`, `greenAsync`, `prPosts`, `DEFAULT_REPORT`); judgment prompts as data files `fleet/roles/*.md`. Every sim is bridged by `tests/test_fleet_suite.py` (sentinel `ALL TESTS PASSED`, 300 s, no network). Suite: `python3 -m pytest`.

**Spec:** #836 (body §The two conditions, §Desired state; comments of 2026-09-11 and 2026-09-16); `docs/superpowers/specs/2026-09-09-tinyapp-state-exams.md` §5 (Deletion owed — the two sentences named; read by the author, absent from every sandbox); `fleet/CONTRACT.md` (the authority for every literal: the Exam environment bullet, the one review round, the Publish card's table).

**Parallelization rationale:** one wave, width 3. The switch with its sim (Task 1), the two role-file deletions (Task 2) and the card cell (Task 3) are three contracts on three surfaces — the engine's review round, two prose files no sim reads for these sentences, and the boot's python card — with no runtime edge between them: Task 3 renders a report row whose verdict string is a shared literal (`skipped-mutant-killed`, in the Context of both tasks) and never needs Task 1's engine to have run, and Task 2's deletions change no prompt any sim pins. Tasks 1 and 3 both touch `fleet/CONTRACT.md` in different paragraphs; that is same-file text and folds. No chain.
