# A task's mutant record is its own state exams — a helper's rigs in the same directory are not the task's survivors

**Grammar:** claims-v1

**Claim:** The mutant reading a task is judged on comes only from the state exams that task's plan names, so a helper's own test rigs that run the exam machinery never show up as the task's survivors on the record, in the reviewer's brief, or on the pull request card. (elicited)
**Summary:** Fixture run-23's second task built the exam helper's reload move, and the helper's own tests drive that move over pages built to fail; every such page wrote a mutant record into the task's directory exactly as a real exam does, so the driver read twelve exams with four survivors where the task had one exam whose mutant died. That misread put four hollow findings in the reviewer's brief, dispatched a reviewer the rule would have skipped, and printed `SURVIVED` on the pull request. After this the driver reads a task's mutant record through the list of state exams its plan actually names, and everything downstream of that record reads the same corrected set; a plan that names no state exam reads the directory as it does today.

**Goal:** land on popmechanic/ultrapowers, read at `935fe1974c7a3d2a1aff4260a5ab65067f0d680b`, one scope rule in `fleet/run-engine.mjs`: the stems of a task's Proof `Test:` paths under `tests/state-exams/` are the task's state exams, and when that set is non-empty every reader of the task's `state-exams/task-<id>/` record — the hollow finding, the reviewer-skip predicate, the `STATE EXAM` block and the report's `tasks[].stateExams` row the pull request card reads — sees only those stems. The rows other files wrote there (a helper's self-tests, run-23's `breach`, `hollow`, `never-persisting`, `never-ready`; run-21's `absent-probe`) are not the task's. A task with no state-exam path keeps BASE's unscoped read, so every sim at BASE, whose Proof names `a_test.sh` or `t1_test.sh`, is untouched. The severity of a real survivor is unchanged (minor) — that decision is shelved on #836 until a real case is on the record.

**Tech Stack:** Node ≥ 20 (`fleet/`), the engine sims under `fleet/tests/test_*.mjs` (sentinel `ALL TESTS PASSED`, bridged by `tests/test_fleet_suite.py`, 300 s per file).

**Spec:** #836 (its 2026-09-17 comment: run-23's twelve rows and four rig survivors; the operator's decision to scope the record and shelve the severity flip); `skills/ultrawrite/references/greenfield-stack.md` §State exams (a TinyApp plan's `peer` task names a state exam under `tests/state-exams/` as its Proof `Test:` path); the fixture helper's `evidenceDir` (`packages/tinyapp-exam/src/evidence.ts`: `<ULTRA_RUN_DIR>/state-exams/task-<ULTRA_TASK>/<stem>-<ULTRA_EXAM_PASS>`) and `examStem` (the basename without `.test.ts`/`.test.tsx`, else without its last extension).
