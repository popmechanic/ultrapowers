# The credential seam — the laptop never leaves a revoked bearer at the edge, and the sandbox proves the bearer before a worker spends a token

**Grammar:** claims-v1

**Claim:** do: launch a run right after a usage read, or onto a bearer the edge no longer honours. see: the launch installs the token it holds, and a run whose bearer is dead parks at boot saying so — the bearer or the edge, with the trace id — before any worker spends a token. (elicited)
**Summary:** This closes the seam that killed runs 92, 95 and 100 this week: a usage read on the laptop could quietly revoke the token the edge was injecting, and the sandbox found out only when a worker mid-wave was refused. After this run every launch puts the token it holds onto the edge whether or not it rotated it, and the sandbox makes one free authenticated call before starting the engine, parking the run with the answer's class and trace id on the record if that call is refused. You get runs that die at second zero with a readable reason instead of forty minutes in, and a launch that cannot be undone by a metering read.

**Goal:** Two measured facts (memory `usage-rotation-revokes-installed-bearer`, `login-edits-shared-bearer`, 2026-09-11) and #903's counsel: (a) `claude-token.mjs usage` rotates an expired account with `install: false`, which revokes the access token installed at the edge; a launch inside `REFRESH_AHEAD_MS` then logs "nothing to do" and installs nothing, so the sandbox runs on a revoked bearer (run-100: `401 OAuth access token has been revoked`); (b) the sandbox has no proof of its bearer before the first worker — run-92 (a 401) and run-95 (an edge 403) each spent a wave to learn it. #903's 403 infra-retry lane is NOT built here and stays open.

**Tech Stack:** Node 24 ESM (`fleet/claude-token.mjs`, sims under `fleet/tests/`), bash (`fleet/sandbox-boot.sh`, sims through `fleet/tests/_sandbox_boot_helpers.mjs`), Markdown (`fleet/CONTRACT.md`, `fleet/RUNBOOK.md`); the sims join the suite through `tests/test_fleet_suite.py`.

**Spec:** memory `usage-rotation-revokes-installed-bearer` and #903 (Shelley's counsel, 2026-09-11); every fact a worker needs is in its task's Context.

**Parallelization rationale:** one wave, two wide. Task 1 is the laptop side (`claude-token.mjs`, its sim, RUNBOOK §3); task 2 is the sandbox side (`sandbox-boot.sh`, its rig, CONTRACT, RUNBOOK's debugging list). Neither consumes a symbol of the other; the one shared file is `fleet/RUNBOOK.md`, edited in two different sections (§3 by task 1, the debugging list by task 2), which is line-disjoint text and folds. No chain.

## Global Constraints

- No secret in any argv, log line, status cell or evidence file: the access token reaches the edge on stdin only, and the sandbox never holds one (its bearer is the edge's placeholder replacement).
- The sims are hermetic: every process a sim starts gets a `simEnv` environment and no sim reaches the network (`fleet/tests/test_sims_are_hermetic.mjs` is the probe).
- Check: bash -n fleet/sandbox-boot.sh

**Acceptance:** suite — the committed suite is the verification.

The choice, and why: of the two shapes the record proposed — `usage` reinstalls when it rotated the account the edge carries, or `refresh` installs unconditionally — this plan takes the second, because it is one edit to one function and needs no lobby read: `usage` would have to learn which account the edge carries (`integrations list --json`'s `--comment account=` is the only place that is written), guard against a second account's rotation, and still miss every other path that rotates a token without installing it. **Claim:** A run whose bearer is dead parks at boot, before any exam or implementer spends a token, and the parked page says which side refused — the bearer itself or exe.dev's edge — with the trace id when the edge answered. (derived)

M2.
