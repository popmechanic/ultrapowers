# The referee is keyed on the lowest-covered clause, and one task per run lands from two implementers so the selector has a reading

**Grammar:** claims-v1

**Claim:** After a run, I open its evidence and see, for every task, one row saying which trigger sent it a referee — a clause Jev covered below the floor, the difficulty rung, both or neither — with that clause's own text in the referee's hand-off; and I see exactly one task per run, the hardest by Jev's reading, landed from two implementers, its landing row carrying both candidates' exam exits, claim and coverage, which one won, and by how much. (elicited)
**Summary:** This changes two things about how a run spends its most expensive worker and its second implementer: the referee is now sent where the landing's own coverage reading says a clause is weakest, not where a difficulty rung that cuts the code tasks in the middle happens to fall, and one task per run is built twice so the score that picks a winner finally has two candidates to separate. It exists because over the four-run drain the rung dispatched referees on 2.20, 2.28, 2.33 and 2.71 but not on 1.92, 1.92, 1.98 and 1.98 while the three clauses that were actually weak — coverage 0.39, 0.70 and 0.13 against 0.93–1.0 elsewhere — got no referee at all, and because every landing of those runs carried k: 1, so the selector decided nothing and cannot be calibrated (n=12 tasks, runs 204–207, read 2026-09-21 — under the 20-task floor, so both ship as experiments). It lets the operator read, per run, which trigger fired and whether the low-coverage referee found the weak leg, and how often two candidates differed on their exam rather than only on their claim; the rollbacks are two cells in the policy file — the coverage floor set to 0, which leaves the rung alone as today, and the probe switched off, which leaves k to the judge as today.

**Goal:** #1209: a `min_coverage` cell beside `review_difficulty_rung` in `factory/policy.json`'s `task.referee`, a pure `refereeTrigger` in `factory/referee.mjs` that answers which trigger fired and the hand-off fact, one `referee:trigger` row per landing, and the referee's prompt carrying the lowest-covered clause's text when coverage fired. #1211: a `dispatch.k_probe` cell in `factory/policy.json`, a pure `kFor` in `factory/kprobe.mjs` that picks the one highest-difficulty task for `k = 2` from the judge's task readings taken once before the first dispatch, a `probeRecord` that shapes both candidates' measurements for the `landing` row, and a `dispatch:k` row naming the probe. The pre-registered readings — referees per run by trigger, blocking findings per referee, whether a low-coverage clause's referee found the weak leg; and over five runs how often the two candidates differed on exam exit versus only on claim — are read off these rows; no census script is added.
**Closes:** #1209 #1211
