# An export that collides with a sibling's contract is a red on the pre-review pass — the driver names it, the repair round fixes it, and no reviewer has to kill the task for it

**Grammar:** claims-v1

**Claim:** A worker that adds a public name a sibling task was contracted to provide is told so before any reviewer reads it, and gets its one repair round to rename or remove it. (elicited)
**Summary:** Run-159's task 3 built the same two helpers its sibling task 2 was contracted to produce, and the folded engine would have been a syntax error; the reviewer caught it, but under the one-round policy a reviewer's block ends the task, so a correct patch died with no chance to rename three helpers. This puts that check where the driver's own evidence already goes: before review, the driver reads the exports the patch adds, and one that matches a symbol a sibling declares and this task does not is a red on the pre-review pass, which buys the same repair round a failing command buys. A worker learns of the collision from the driver instead of from a fatal review, the reviewer sees the record of it, and a plan whose tasks stay inside their contracts sees nothing new.

**Goal:** land on popmechanic/ultrapowers, read at `cf289581ebe2fa8dc23a8683c6d4e31c835d2ae2`, one new red on the driver's pre-review pass in `fleet/run-engine.mjs`: after the `Run:`, exam, `Check:` and handshake reads, the driver scans the captured patch's ADDED lines for top-level exported declarations and, for each exported name that equals the symbol token of a `Produces:` entry of another task of the plan and is not the token of one of this task's own `Produces:` entries, pushes one red line onto the pass and appends one `driver:finding` row at `round: 0` with `actor: implementer`. The red buys `fix:<id>:0` exactly as a red `Run:` does; a task with no such export sees the pass it sees at BASE. The contract names the red and the row.

**Tech Stack:** Node ≥ 20 (`fleet/`), the engine sims under `fleet/tests/test_*.mjs` (sentinel `ALL TESTS PASSED`, bridged by `tests/test_fleet_suite.py`, 300 s per file).

**Spec:** #1057's correcting comment of 2026-09-17 (task 3 of run-159: `failed: fix-loop-exhausted`, `fixIterations: 0`, the reviewer's one blocking finding "Duplicate module-level declarations after the fold: this task's hunk adds `export const receiptText` and `export const receiptPaths` … sibling Task 2 … adds `export const receiptPaths` … `SyntaxError: Identifier 'receiptPaths' has already been declared`"; task 3's Interfaces read `Produces: none`, task 2's `Produces: receiptPaths(list: string[]) -> string[]`); #964 Task 2 (one review round, a blocking finding ends the task; the only repair round is the pre-review `fix:<id>:0`); #713 Task 1 (the pre-review pass and its one repeat); the receipts plan of 2026-09-16 (`driver:finding`, `RECEIPT_KINDS`, the `FACTS:` block).
