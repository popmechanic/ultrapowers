# A lockfile is regenerated at the fold, never resolved — a task's patch never carries one, and the driver rebuilds it from the merged manifests before the frozen install and the suite

**Grammar:** claims-v1

**Claim:** When several tasks in one run add packages, the run's lockfile is rebuilt from the merged manifests at each fold, and no worker is ever asked to merge a lockfile by hand. (elicited)
**Summary:** Two fixture runs parked because three tasks each installed packages, their patches all touched the lockfile, and the fold handed that file to a resolver that could not finish: a lockfile is machine-written from the manifests, and asking a model to merge one is asking it to reproduce the installer's output under a clock. After this, a lockfile never rides in a task's patch, and at each fold the driver rebuilds it from the merged manifests with the installer's own non-frozen command and commits the result before the frozen install and the suite run. A plan may let every task install what it needs, the one-task-owns-installs workaround retires, and the pull request carries a lockfile in step with its manifests.

**Goal:** land on popmechanic/ultrapowers, read at `4434e0687178d02cfb658ea62467e937e6eda663`, #1050's desired state in its minimal form: (1) the patch capture excludes lockfile basenames the way it already excludes unnamed binaries, so the kernel never narrates a lockfile conflict and `resolveConflicts` never sees one; (2) the launcher derives, beside the frozen bootstrap it already derives, the installer's non-frozen twin as `regenerateCmd`; (3) at each wave fold, when the candidate changed a manifest, the driver runs that command on the candidate tree, commits any changed lockfile onto the candidate with one `driver:regenerated` event, and only then runs the frozen bootstrap and the suite as it does today. The fold's existing re-install (#825) is `bun install --frozen-lockfile` / `pnpm install --frozen-lockfile` / `npm ci`, which refuse a manifest their lockfile disagrees with — so regeneration is a step of its own, before it, and not a property of it.
**Closes:** #1050

**Tech Stack:** Node ≥ 20 (`fleet/`), the engine sims under `fleet/tests/test_*.mjs` (sentinel `ALL TESTS PASSED`, bridged by `tests/test_fleet_suite.py`, 300 s per file); Python 3 for `skills/ultrapowers/scripts/ultra_run.py` and its pytest under `tests/`.

**Spec:** #1050 (run-19: `bun.lock` to `resolve:wave1:1:1`, SIGTERM at the worker timeout, wave 1 blocked; its comment of 2026-09-16: `BOOTSTRAP_MANIFESTS` is the seed, nothing keeps `bun.lock` out of `resolveConflicts`); the sitting of 2026-09-17 (the frozen-install fact: `derive_bootstrap_cmd`'s JS rungs are all frozen, so the #825 re-install cannot regenerate); #825 (the candidate's own install before its suite); #714 (the capture's drop rule and `capture:dropped`); #665 (the adjacent species, not this plan).
