# A patch that puts a NUL byte into a text file is a red on the pre-review pass — the driver names the byte, the repair round removes it, and no fold reads the file as binary

**Grammar:** claims-v1

**Claim:** A worker whose patch puts a stray control byte into a source file is told so before any reviewer reads it, and gets its one repair round to remove it, so no later merge stalls on a file the tools can no longer read as text. (elicited)
**Summary:** Today a single invisible byte reached main: an implementer wrote a string separator as the raw character instead of its two-letter escape, every test passed, the reviewer saw ordinary code, and from then on git and the fold kernel treated the engine's main file as binary, so the next run's merge onto main stalled with no one to resolve it. After this, the driver checks each patch before review for a file that was readable text and now carries that byte, and treats it as one more red on the pass, which buys the same repair round a failing test buys. The worker fixes it in seconds, the record shows the byte, and no run pays a hand merge for it.

**Goal:** land on popmechanic/ultrapowers, read at `4434e0687178d02cfb658ea62467e937e6eda663`, #1063's desired state: one more red on the driver's pre-review pass in `fleet/run-engine.mjs`, beside the export-collision red of #1060 — for each path the captured patch touches, when the file in the graded clone carries a `0x00` byte and the blob at the task's dispatch head was text or absent, the driver pushes one red naming the path and the byte offset and appends one `driver:finding` at `round: 0`; the red buys `fix:<id>:0` like every other red of the pass, and a task whose patch introduces no NUL sees the pass it sees at BASE. The contract names the red and the row.
