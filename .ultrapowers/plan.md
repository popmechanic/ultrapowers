# The relaunch ghosts — a reuse refusal names its cause, a prior run's attention is cleared at Setup, and a finding against the exam buys the examiner one more round

**Grammar:** claims-v1

**Claim:** A relaunch tells me why it reused nothing, never shows me the old run's verdict on the new run's tasks, and a review finding against an exam gives the examiner one more round before the task is called exhausted. (elicited)
**Summary:** This makes relaunching a plan after a failed run start clean instead of carrying three leftovers from the run before it. It exists because runs 14, 15 and 16 on the fixture app each carried one — the relaunch could not say why it redid finished work, it showed the earlier run's failure on a task that had barely started, and a task was called exhausted when the only party who could have fixed it, the peer who wrote the exam, was never asked. After this run a relaunch names the reason it reused nothing, the earlier run's marks are cleared before any worker starts, and a finding against the exam sends the exam back to its author once before the task is given up on.

**Goal:** close the three relaunch defects of #1037 on the plugin repository popmechanic/ultrapowers, read at `901fc874923210207e041f947407b8ea519c1ab2`: the reuse fold's own reason (a conflict count, a materialize refusal, a missing verdict) stays in `judgmentCalls` while the `driver:reuse` event and the log say only "did not produce a head" (`fleet/run-engine.mjs` line 1936); the attention poll's baseline is `ok` for every task so a `needs-human` the earlier run's `kataMark` left on the reused issue is read as a fresh move fifteen seconds in (run-16 lines 14 and 48 of its `events.jsonl`); and the one review round ends a task `fix-loop-exhausted` on a blocking finding whatever file it names, so a finding against the examiner's file never reaches the examiner (run-15 task 1, `fixIterations: 0`).
**Closes:** #1037

**Tech Stack:** Node ≥ 20 (`fleet/`), the engine sims under `fleet/tests/test_*.mjs` (sentinel `ALL TESTS PASSED`, bridged by `tests/test_fleet_suite.py`), the fold kernel `skills/ultrapowers/kernel/` called by the engine as `python3`, the hub's REST API through `fleet/kata-client.mjs` (stubbed in every sim).
