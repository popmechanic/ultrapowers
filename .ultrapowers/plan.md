# A fold only when it releases work — the epoch engine stops paying a suite per landing, and the hub shows landed and adopted

**Grammar:** claims-v1

**Claim:** When I read a run's record, every fold either made a queued task ready, closed the run, or adopted work that had waited a full suite's length — a plan with no edges folds once, and a task lands on the hub as landed, then adopted, never as needing a human when it doesn't. (elicited)
**Summary:** This is the fix the Phase C reading asked for: run-134 replayed a ten-task plan in five folds of a five-minute suite where the wave engine paid one, because the engine folds whatever has landed the instant a lane frees, whether or not that fold lets anything start. It exists so a fold is bought only when it buys something — a queued task becomes ready, the run is ending, or a result has sat unadopted for a whole suite's length — and so the hub tells the truth about a task between its worker ending and its fold, instead of stamping every clean task as needing a human. After this run a plan with no edges folds once at the end, a chain folds exactly when its consumer can start, and a run's issues read open, landed, adopted, done.

**Goal:** #979's decision of 2026-09-15 (operator, on the run-134/135 reading posted the same hour): the fold rule with three triggers — release, end, age — and the hub-state fix beside it (the SessionEnd hook's `needs-human` stamp cleared when the driver takes a result; `work.state` `landed` then `adopted` on each task issue). The age threshold is an engine argument so a sim can set it: `foldAgeMs`, default the larger of 60 s and the baseline suite's measured wall; `0` is the BASE behaviour, a fold at every landing, which is how the two sims that pace their reviewers on a fold keep their scenarios.
**Closes:** #979

**Tech Stack:** Node 22 ESM under `fleet/` (sims `fleet/tests/test_*.mjs`, each printing `ALL TESTS PASSED`, bridged by `tests/test_fleet_suite.py` which globs them — a new sim rides the suite with no registration; the engine sims drive `runEngine` through `fleet/tests/_engine_helpers.mjs`'s `rig`, real git and the real fold kernel, only `agent` canned). **Spec:** #979 (the phase, its 2026-09-15 reading comment with the run-134 fold timeline and the run-135 row); `fleet/CONTRACT.md`'s evidence bullet (the ready-set paragraph) and its kata section (`work.attention`, the re-edge); the kata write log of runs 134 and 135 on their evidence tags (`kata.jsonl`), which is where the `needs-human` stamp was read.

Task 1 (the fold rule) and Task 2 (the hub's landed and adopted state) both edit `fleet/run-engine.mjs` and `fleet/CONTRACT.md` in disjoint regions — the claim-and-lane code around `claimEpoch` versus the kata write sites `settleResult` and `kataAdopted`, the evidence bullet versus the kata section — and that text folds. Neither consumes the other's runtime: the landed stamp is written at the instant a result is captured, which is the same instant under either fold rule, and the adopted stamp rides the fold whenever it happens. ### Task 1: A lane folds only when the fold releases a queued task, ends the run, or adopts a result that has aged a suite's length

**Claim:** When I read a run's record, every fold either made a queued task ready, closed the run, or adopted work that had waited a full suite's length — and a plan with no edges folds once. (derived)
Machine: M1. A lane that frees claims an epoch only when at least one of three holds at that instant, and the `driver:wave-adopted` (or `driver:wave-blocked`) event it produces carries `why` naming which: `released` — some task not yet dispatched, not failed and not downstream of a failed or blocked task, that is not ready now, has every predecessor an edge names either adopted or among the pending results, and the event also carries `released: [<those task ids>]` in plan order; `end` — after this landing no worker is in flight, no fold is running, no task is ready and nothing is pending but these results; `aged` — the oldest pending result has waited `foldAgeMs` milliseconds or more since it landed (so `0` holds at the landing itself). M2. `foldAgeMs` is read from the run's arguments when it is a non-negative number; otherwise it is the larger of `60000` and the wall, in milliseconds, of the baseline suite the run measured (the age clause is off until the baseline has settled); with `foldAgeMs: 0` every landing folds at its own instant, which is the BASE rule. M3. A run of three tasks with no edges, whose implementers land at three different times with `foldAgeMs` large, adopts all three in exactly one epoch with `why: 'end'`; the same run with `foldAgeMs: 0` adopts them in more than one epoch, the first `why: 'aged'`. M4. A run of tasks A, B, C with edges A→C and B→C, A landing first, adopts A and B together in one epoch with `why: 'released'` and `released: ['C']` only once B has landed, C is dispatched after that adoption on its head, and C's own landing is adopted in a second epoch with `why: 'end'`; a run where A lands, then nothing else lands for longer than a small `foldAgeMs` while B is still running, adopts A alone with `why: 'aged'`. M5. A lane waiting with nothing ready and results pending wakes on its own when the oldest pending result reaches `foldAgeMs`, without another landing. M6. `fleet/CONTRACT.md`'s evidence bullet states the three triggers and `foldAgeMs` with its default and its `0` reading, and still carries, in this order, the words `epoch`, `ready`, `slot frees`, `driver:wave-adopted` and `descendant`. M7. `fleet/tests/test_run_engine_ready_set.mjs`, `fleet/tests/test_run_engine_joined_proofs.mjs` and `fleet/tests/test_run_engine_proof_runs.mjs` — all three edited by this task — pass on the patched tree: the first's header M2 text states the new rule, its scenario `c1` is re-aimed to one epoch of `['X','Y','Z']` with `why: 'end'`, and every other scenario of that sim (`a1`, `a2`, `b1`, `b2`, `d1`, `d2`, `e1`, `e2`), whose subject is not the fold trigger, passes `foldAgeMs: 0` to the engine so its BASE expectations hold unchanged; the other two sims pass `foldAgeMs: 0` in their rigs for the same reason.

**Authorized-by:** #979 (the operator's decision of 2026-09-15 on the reading, the "fold only when it releases work, or at the end" option); #979's 2026-09-15 reading comment.

**Context:** At BASE (`a94143bb`) the ready set lives in `fleet/run-engine.mjs` from the `// ── the ready set: lanes, epochs, one fold at a time (#979)` banner (~3359): `pendingResults` (captured, unadopted mergeable results in landing order), `inFlight`, `foldingLanes`, `epochClaimed`, `landingWaiters` with `nextLanding()` / `announceLanding()` (~3417–3425), `claimEpoch()` (~3447: returns every pending result when nothing has claimed an epoch and the run is not parked, else `null`), `isReady(t)` (~3567: not dispatched, not failed, not `blockedByDep`, every `predecessorsOf(t)` in `adoptedIds`), `takeReady()` (~3579), `settleResult(r, replacing)` (~3635: records the row, pushes a mergeable result onto `pendingResults`, `announceLanding()`, then `return claimEpoch()` — the claim is taken at the landing's own instant, which is the rule to keep), `foldEpoch(merged)` (~3695: awaits `baselineSettled` on the first fold, numbers the epoch, runs the kernel, appends `driver:wave-adopted {wave, tasks, headSha}` at ~3761 or `driver:wave-blocked` at ~3885), `foldPending`, `dispatchOnce`, `retryParkedInfra`, and the lane loop `lane()` (~3989: `claimEpoch()` at the top of each turn, then `takeReady()`, then the `quiet` test — `inFlight === 0 && foldingLanes === 0 && !epochClaimed && pendingResults.length === 0` — which retries a parked-infra result or returns, else `await nextLanding()`). The rule goes into `claimEpoch` as a predicate over that state: `released` reads `PLAN` for a task with `!dispatchedIds.has(id)`, not failed, not in `blockedByDep`, not `isReady`, whose every predecessor is in `adoptedIds` or is the `task` of a pending result; `end` is `inFlight === 0 && foldingLanes === 0` with `takeReady`'s answer empty — reorder `lane()` so a pending set with nothing else to do is folded before the run is judged quiet, or the last lane returns with results never adopted; `aged` compares the oldest pending result's landing time, which `settleResult` must now record on the result (`landedAt: Date.now()`), against the threshold. The threshold: `args.foldAgeMs` when `Number.isFinite` and `>= 0`; else `Math.max(60000, baselineWallMs)` where `baselineWallMs` is measured around the existing `sh(testCmd, baselineDir)` that becomes `baselineSettled` (~1963) — record the wall in `settleBaseline` beside `passed`/`output`; before it settles the age clause is off. Waking for age (M5): a lane that reaches `await nextLanding()` with results pending and no fold running races the landing against a timer of `threshold − (now − oldest.landedAt)` (unref'd, cleared on the landing), then loops so `claimEpoch` runs again; `foldAgeMs: 0` makes the aged clause true at every landing, so `settleResult`'s own claim folds as at BASE.
