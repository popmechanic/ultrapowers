# Amendments are first-class rows — a worker's change to a clause, a Files set or a sim is a typed event the reviewer reads, the pull request lists and the release counts

**Grammar:** claims-v1

**Claim:** After a run I can read every place a worker changed what the plan asked for — which task, what kind of change, what it did and why — on the run's record, in its pull request and in the release's count, and the reviewer judged each change instead of undoing it. (elicited)
**Summary:** This makes a worker's amendment to the plan a first-class row of the run instead of a sentence buried in a judgment call: when a worker edits a file the plan did not list, reads a clause differently to make the exam pass, or re-aims a sim outside its files, it declares that as a typed amendment, and the driver writes it on the evidence branch, hands it to the reviewer as a lens, prints it on the pull request card and counts it in the release census. It exists because the doctrine said the plan binds while the record showed good workers amending it whenever the amendment was small and honest — run-133's first task made four such changes and merged clean, run-2 died on a reviewer who could not tell whether one was lawful — and a rule that is honoured only sometimes leaves both the author and the reviewer guessing. After this run the plan is a submission the worker may amend in the open, every amendment is on the record per run and per task, the doctrine says so in as many words, and a leg no implementation can pass still parks the task for the plan exactly as it does today.

**Goal:** #990's decision of 2026-09-15 (operator): amendments are first-class rows, as five independent contracts on BASE `5a8f1ebd` — (1) the worker declares each amendment in a typed `amendments` field of its reply and the driver appends one `driver:amendment {task, amends, what, why}` event per entry and lists them on `report.json`; (2) the reviewer receives the task's amendments as an `AMENDMENTS:` lens and its role says a declared amendment is judged, never reverted; (3) the record names the event and the report key — `fleet/CONTRACT.md`, the report reference — and the pull request card lists them; (4) the release census counts them per run; (5) the doctrine in `CLAUDE.md`, the authoring skill and its gotchas says the plan is a submission, not a contract. The reading to keep is amendments per run and per task; #728's record carries the rows.
