# The boot trim: rendering and the board leave `factory/boot.sh` for the engine's own modules, and publish stays shell

**Grammar:** claims-v1

**Claim:** `wc -l factory/boot.sh` ≤ 300, reported on the pull request as a design note, never a clause. Every decision stays in shell — draft or ready, hold, the 405→refold loop, the state written — and each Node call returns a string or a row, never a verdict (publish is shell, not a seam: run-186). (quoted from #1222)
**Summary:** This slims the script that runs each sandbox from start to finish, moving the parts that only render text or talk to the task board into the engine's own modules while every decision about publishing stays exactly where it was. It exists because that script had grown to two and a half times the size the design allows, and a script that big hides defects: one of its record rows was missing its timestamp, and the contract contradicted itself on how often evidence is committed. After this run the script reads top to bottom as the sequence it performs, every row it writes is stamped, the pull request's own description and the commit cadence are written down in the contract, and the script as it was stays in history as the rollback.

**Goal:** #1222 (map #1131, rule 6): a new `factory/record.mjs` that renders rows, the status page, the pull request body and the policy read; `factory/board.mjs` gaining the spoke config, the readiness wait and the run close; `factory/preflight.mjs` taking the credential probe; and `factory/boot.sh` trimmed to the shell that decides — with the line count reported, not proven.
**Closes:** #1222

**Tech Stack:** Node 24 ESM and bash; no new npm dependency.
Spec: none on disk — issue #1222 and the boot tally read at BASE are the brief, and everything a worker needs is in its own Context. The sandbox holds no spec.
