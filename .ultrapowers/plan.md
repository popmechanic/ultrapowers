# A run's leftover findings land in the ledger where repeats surface by count

**Grammar:** claims-v1

**Claim:** A run's leftover findings land in the ledger where repeats surface by count; nobody files a per-run issue by hand. (elicited)

**Goal:** #869 — the per-run `watch-item` "fleet run-N residuals" issue (ten of them on 2026-09-09,
none read before a three-agent audit) is replaced by the experience compiler's own shape (#414):
the sandbox writes each residual as one row of `.ultrapowers/runs/<N>/residuals.jsonl` on the
evidence tag and files no issue; ultralearn's residual counter appends those rows to the ledger,
keyed by `(file, normalized text)`, and its report names the residuals seen in two or more runs
or on two or more files — the candidates a sitting consolidates into one issue per theme, by hand.
The issue-filing step is deleted with the change (deletion owed per guard: the lines are named in
task 1's Context). Two choices made in place of a question, each with the least machinery: (1) the
ledger stays append-only, as `catch_counter.append_rows` keeps it — one row per residual per run,
carrying a `key` derived from `(file, normalized text)`, and the report folds by key, so "merged"
means folded at read time and no existing ledger line is ever rewritten; (2) `sha` in a residual
row is the run's base sha, the one 40-hex the assignment always carries, because a row written at
a transition before publish has no integration head to name.
**Closes:** #869

**Tech Stack:** POSIX `sh` (`fleet/sandbox-boot.sh`, its one-reader `python3 -c` idiom) and Node
sims (`fleet/tests/test_*.mjs`, run under `tests/test_fleet_suite.py` and by `node`, sentinel
`ALL TESTS PASSED`); Python 3 stdlib for `skills/ultralearn/scripts/*.py` (no model call, no
network, no git write) with `python3 -m pytest` from the repo root.

**Spec:** none — #869 is the spec; each task quotes or derives from its desired-state paragraph.

**Parallelization rationale:** one wave, width 2. Two tasks on two disjoint file sets — the
sandbox side (`fleet/sandbox-boot.sh`, `fleet/CONTRACT.md`, the boot rig, the docs pin) and the
ultralearn side (`skills/ultralearn/`, its own exam) — with no `Consumes:` between them: the
residual counter reads `residuals.jsonl` rows the exam writes by hand, so nothing in task 2 needs
task 1's runtime behaviour. The one row shape they share is the literal in both Contexts. No chain.

(quoted from #869)
Machine: M1. `python3 skills/ultralearn/scripts/residual_counter.py <path>… --ledger <file>` appends, for every directory that holds a `residuals.jsonl` among the paths and their descendants, one ledger row per line of that file, each row exactly the keys `id`, `kind`, `key`, `runId`, `task`, `file`, `line`, `residualKind`, `text`, `sha` with `kind` `residual`, `runId` the line's `run`, `residualKind` the line's `kind`, and `sha` the line's `sha`.
M2. Each appended row's `key` is the first 16 hex digits of the SHA-256 of the row's `file` (the empty string when the line's `file` is null) + newline + the normalized text — the text's whitespace runs collapsed to one space, stripped, lowercased — and its `id` is the first 16 hex digits of the SHA-256 of `<runId>` + newline + `residual` + newline + `<key>`; the same residual text on two runs yields two rows with equal `key` and different `id`.
M3. The counter is append-only and idempotent: a second run over the same paths appends nothing and leaves the ledger's bytes unchanged, an existing findings line (no `kind`) is never rewritten, the ledger's parent directories are created when absent, and without `--ledger` nothing is appended; it prints exactly one stdout line `<n> file(s) counted, <a> row(s) appended, <s> already recorded`.
M4. `python3 skills/ultralearn/scripts/residual_report.py --ledger <file>` groups the ledger's `residual` rows by normalized text — every other row kind contributes nothing — and prints `## Residual candidates` then one line `- <text as first seen> | runs: <distinct runIds, sorted, comma-space joined> | files: <distinct non-null files, sorted, comma-space joined, or - when none>` per group whose distinct `runId` count is at least 2 or whose distinct non-null `file` count is at least 2, ordered by distinct-run count descending then text ascending, and the one line `(none)` when no group qualifies; a group seen in one run on one file is not listed, and a ledger path that does not exist reads as no rows.
M5. `skills/ultralearn/SKILL.md` has a section whose heading line is `## The residual counter`, between `## The catch counter` and `## Verb 2`, naming `residual_counter.py`, `residual_report.py`, `residuals.jsonl`, the `(file, normalized text)` key and the two-runs-or-two-files rule, and no `--` flag in the section is absent from the two scripts' `--help`; `validate_skill.py` accepts the skill.
