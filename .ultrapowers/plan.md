# The worker's own words raise the hand: each kata note is read as it lands, attention comes from the note and not the SessionEnd hook, and a named plan defect reaches the run's issue

**Grammar:** claims-v1

**Claim:** do: open the run's issue after a worker writes that it is stuck or that the task text is wrong; see: that task marked needs-human from the worker's own note, and the plan defect mirrored on the run issue as a comment. (elicited)
**Summary:** Workers write down when they are stuck and when the task text is wrong, and today those sentences are drowned by a hook that marks every clean task as needing a human. This plan reads each note as it lands, raises the hand from the note instead of the hook, and forwards a named plan defect to the run's issue so the next author sees it. Real hand-raises stop being missed; after five runs the record says how many were caught, and the rollback is the hook.

**Goal:** #1095's proposal, as an `experiment` under the n=5 floor with its rollback named: the sitting's two question sets and two readers over the Jev client run-177 merged (`fleet/jev-questions.mjs`, functions over `fleet/jev-client.mjs`'s `ask`); the engine reading every worker note off the hub's events page as it lands and writing the five answers beside it as a `jev:note` row; `work.attention` set `needs-human` from a note — an implementer's or fix session's at `stuck ≥ 0.7`, an examiner's only when the note is also a `blocker` — while the SessionEnd hook's stamp keeps landing as its own `driver:attention-hook` row and no longer sets attention by itself; a note reading `plan_defect ≥ 0.7` mirrored as one comment on the RUN issue naming the task and the sentence; and every `driver:amendment` row carrying Jev's `compelled`, `plan_fault` and `magnitude`, which the authoring census's `totals:` line reads. Rollback: the hook sets attention as today; the note answers stay as data.
**Closes:** #1095
