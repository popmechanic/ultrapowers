# A Flock run keeps its telemetry

**Grammar:** claims-v1
**Claim:** After a Flock run, its permanent record says what went wrong: the output of every check that was red at the end and, for a draft, a one-page failure brief for the next agent to read first; and it keeps the board's moves, every merge with file texts as fingerprints, and which files each tested snapshot changed. (elicited)
**Summary:** A finished Flock run now keeps what an agent needs to fix it: the actual output of every check that was still failing, and for a draft a one-page brief saying why it stopped, what failed, and what the engine last did. Today a run records only that a check failed, not what it printed, and the board, merge and snapshot files vanish when the run's machine is removed, so a failure like run-247 or run-252 can't be diagnosed afterwards. The brief is what the builders of a fix, or a session fixing the engine itself, read first, and the whole record stays small on every run.

**Goal:** Keep what went wrong in a Flock run, and its board, weave and snapshot telemetry, in its evidence tag, compactly.
**Tech Stack:** Node 24 (ESM); bash (`factory/boot.sh`).

Spec: the operator's request of 2026-09-28 (pasted from a reviewing agent), and the measurements below.

## Global Constraints

- Measurements behind the shape (2026-09-28, n=2: radio-station run-2 on its VM, and a scripted one-task run on this repo at `899757d3`): `snapshots.json` was 492,289 bytes for 3 snapshots of an 18-file app, and 3,909,303 bytes for 1 snapshot of this 252-file repo, because each snapshot holds every file in full; the changed files were 2,278 to 9,385 bytes per snapshot on run-2 and 54,027 bytes on this repo. `weave-ops.jsonl` was 15,277 and 64,393 bytes, and its `rewrite` rows carry whole files in `content`. `board-ops.json` and `board.json` were about 1 KB each.
- A failed run's record is for the next agent: it says what went wrong in the checks' own words, not only that they exited non-zero (operator, 2026-09-28).
- The evidence never holds a whole snapshot, the raw `weave-ops.jsonl` or `checks/`: only `board-ops.json`, `board.json`, `weave-ops.digest.jsonl`, `snapshots.jsonl`, `snapshot-texts.json`, `red-checks.json` and `failure.md`, beside what it holds today.
- Evidence files are named one by one, never `git add -A`, and added with `add -f` so a target's `.gitignore` cannot drop them; a file the engine did not write is skipped and never fails the boot.
- The factory engine (`--kind factory`) writes none of these names and keeps working unchanged.
- Check: python3 -m pytest -q tests/test_fleet_suite.py -k boot

### Task 1: The Flock writes a compact record of its snapshots and weave

**Type:** implementation

**Files:**
- Modify: `factory/flock/engine.mjs`

**Claim:** After a Flock run, its permanent record says what went wrong: the output of every check that was red at the end and, for a draft, a one-page failure brief for the next agent to read first; and it keeps the board's moves, every merge with file texts as fingerprints, and which files each tested snapshot changed. (derived)
Machine: M1. A one-task scripted run whose builder writes `hello.txt` as `hi\n` leaves in its run directory a `snapshots.jsonl` whose last row's `changed` is exactly `[{"path":"hello.txt","sha1":<sha1 of "hi\n">,"bytes":3}]` with an empty `deleted` (the unchanged base file `README` is not listed); a `snapshot-texts.json` with `limit_bytes` 524288, `truncated` false and that text under its sha1; and a `weave-ops.digest.jsonl` in which no row has `content` and every `rewrite` row has `content_sha1` and `content_bytes`. M2. When a changed text would push the kept texts past `limit_bytes` (a 600,000-byte `hello.txt`), its row still lists the path, sha1 and bytes, the text is not kept, `truncated` is true and `bytes` stays at or under the limit.

**Authorized-by:** the operator's request of 2026-09-28; the weave-digest pick (operator, 2026-09-28: "Keep it, file texts as hashes")

**Interfaces:**
- Consumes: nothing
- Produces: nothing

At the end, beside those (keep them; they are the local copy), also write: `snapshots.jsonl`, one row per tested snapshot, `{snap, t, changed: [{path, sha1, bytes}], deleted: [path]}`, where changed means the path exists with text different from the file in `BASE_DIR` (or not there at all), and deleted means it does not exist in the snapshot but does in `BASE_DIR`, paths sorted; `snapshot-texts.json`, `{limit_bytes: 524288, bytes, truncated, texts: {sha1: text}}`, each distinct changed text kept once, in snapshot order, while the running total stays within the limit (a text that would exceed it is skipped and sets `truncated`); and `weave-ops.digest.jsonl`, the rows of `weave-ops.jsonl` with any `content` string replaced by `content_sha1` (sha1 hex of the text) and `content_bytes` (its UTF-8 byte length). sha1 is `crypto.createHash('sha1')` over the text. The 512 KB limit is about ten times the largest changed text measured (54,027 bytes on this repo, n=2 runs, 2026-09-28). These names are shared with the boot's copy step: `board-ops.json`, `board.json`, `weave-ops.digest.jsonl`, `snapshots.jsonl`, `snapshot-texts.json`, `red-checks.json` and `failure.md`.
