# Test selection offers only the tests that read a changed file, and a task with nothing to offer says so

**Grammar:** claims-v1

**Claim:** A candidate is offered only when it imports, spawns or names a path the patch touches — a matched path or an exported symbol, never a stem or a bare word — and a task with no such candidate asks Jev nothing and writes `select:exam` with `candidates: []` and `why: none`. The `covered` cell is filled or removed. (quoted from #1208)
**Summary:** This changes which existing tests a run offers the judge when a task's change lands. It exists because over the four-run drain the offered tests were picked by common words — the same eight files for nearly every task, none of them reading what changed, 344 answers with none above 0.38 (n=4 runs, 204–207). After this run a test is offered only when it actually reads a changed file and a task with nothing to offer is recorded as such; it ships as an experiment one run under the floor, and its rollback is the word-matching needles as they stand today.

**Goal:** #1208: `factory/select.mjs`'s `candidateTests` matches a test only on a touched path, an import of a touched module or an exported symbol on an import line — the stem, bare-word symbol and directory needles go — and the engine's `select:exam` row is written for every examined task, `candidates: []` and `why: 'none'` when nothing was offered. The pre-registered readings — candidates offered per run, the share of `M__t` answers at or above 0.5, tests selected and how many of those failed — are read off the `select:exam`, `select:landing`, `catch` and `jev` rows this engine already writes; no census script is added.
**Closes:** #1208

**Tech Stack:** Node 24 ESM for the factory and its exams, no new npm dependency; JSON for the policy cells.
Spec: none on disk — issue #1208 is the brief, and everything a worker needs is in its Context. The sandbox holds no spec.

Machine: M1. `candidateTests({ files, read, paths, symbols, exclude, cap })` offers a test file whose text contains one of `paths` verbatim, with `why` `'path'` and that path among its `hits`.
M2. It offers a test file one of whose import lines — a line that, after leading whitespace, begins `import ` or `from `, or that contains `require(` — holds the stem of a touched path's basename (`plan_parse` for `skills/ultrapowers/scripts/plan_parse.py`) as a whole word, with `why` `'import'` and that stem among its `hits`; and one whose import line holds one of `symbols` as a whole word, with `why` `'symbol'`.
M3. A test file whose only mentions are a touched file's stem outside an import line, one of `symbols` outside an import line, or a directory a touched path sits under is not offered; and a call whose needles match no file answers exactly `[]`.
M4. `factory/select.mjs` exports `examSelectionRow({ task, found, covered })`, which answers `{ kind: 'select:exam', task, candidates, covered, why }` — `candidates` the paths of `found` in order, `covered` as given, and `why` an object from each path to its `why` when `found` is non-empty and the string `'none'` when it is empty.
M5. In `factory/engine.mjs`, `examine` appends `examSelectionRow(…)` to the events for every task that reaches candidate finding — whether or not a candidate was found and whether or not Jev answered — with `covered` the covering reading's `covered` array, `[]` when there was no candidate or no answer; `readCovering` is asked only when at least one candidate was found; and the engine no longer names `dirNeedles`.
M6. `factory/policy.json`'s `select` cell no longer carries `dir_needles` and carries a `needles` cell with `kinds` exactly `["path", "import", "symbol"]`, `n` 4, a `window` naming runs 204–207, `experiment` true and a `rollback` string naming a revert.

**Context:** You see this task body and nothing else. `factory/select.mjs` (207 lines) is the pure candidate finder: `candidateTests({ files, read, paths = [], symbols = [], exclude = [], cap = 8, dirNeedles = true })` builds needles in `buildNeedles(paths, symbols, dirNeedles)` — for every non-test path a `path` needle (the path itself), a `stem` needle (`stem(basename(p))`), and with `dirNeedles` one `dir` needle per ancestor directory; then one `symbol` needle per entry of `symbols` — drops needles shorter than 4 characters, and `matchesNeedle(text, needle)` reads a needle carrying `/` or `.` as a substring and any other as a whole word (`wholeWordMatch`, boundary `[A-Za-z0-9_$]`) anywhere in the file. `KIND_PRIORITY` is `['path', 'stem', 'symbol', 'dir']`, `why` is the first kind in that order among a file's hits, results sort by non-dir hits, then dir hits, then path, and are cut at `cap`. **The defect (n=4 runs, 204–207, 12 landings):** `stem`, bare-word `symbol` and `dir` needles hit common words — `select`, `settled`, `exit`, `factory`, `fleet` — so nearly every task was offered the same eight files (`tests/test_plan_parse.py`, `fleet/tests/test_launch_duplicate.mjs`, `fleet/tests/test_sims_are_hermetic.mjs` in 10 of 12 lists), 344 `M__t` answers had none above 0.38, and the one test ever selected covered nothing the task touched. **The rule now:** three kinds, `KIND_PRIORITY` `['path', 'import', 'symbol']`. `path` — the file's text contains a touched path verbatim (a relative import `'../../factory/select.mjs'`, a spawn `node fleet/launch.mjs`, a prose mention all count). `import` — an *import line* of the file holds the touched file's stem as a whole word; an import line is one that, after leading whitespace, begins `import ` or `from ` (Python `from plan_parse import parse_plan`, ESM `import { x } from '../launch.mjs'`), or that contains `require(`; the stem is `stem(basename(p))`, still at least 4 characters, and a test-file path is still no needle. `symbol` — an import line holds one of `symbols` as a whole word; the same word anywhere else in the file is not a hit. No `stem` kind, no `dir` kind, no `dirNeedles` option (an extra key a caller still passes is ignored by destructuring). `hits` carries the matched values, `why` the first kind in priority order, ordering by hit count then path and the `cap` cut stay as they are; `excerptFor`, `symbolsOf` and `commandFor` are unchanged. Add `examSelectionRow({ task, found = [], covered = [] })` beside them, pure, answering exactly `{ kind: 'select:exam', task, candidates: found.map((c) => c.path), covered, why }` with `why` `Object.fromEntries(found.map((c) => [c.path, c.why]))` when `found` has entries and the string `'none'` otherwise.
