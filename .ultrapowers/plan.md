# The card — a PR you can approve in one read

**Grammar:** claims-v1

**Claim:** do: open a fleet PR. see: at the top, in plain language, what this is, why it exists and how it helps me; then whether it is merge-ready; then the sentence I signed; then one row per task saying what was promised and how it was proved; the reviewers' notes are a count, and every sha and receipt is folded away below. (elicited)

**Summary:** This changes what a fleet pull request says when it opens. Today the body leads with commit hashes, a block of raw JSON and a wall of reviewer bullets, so the person deciding whether to merge has to hunt for the answer. After this run the body opens with a plain-language summary the plan's author signed, says in one line whether the run is ready, quotes the sentence the operator signed, and shows one row per task with what was promised and how it was proved, with the machine record folded away underneath.

**Goal:** Decisions 8, 9, 10 and 11 of the #871 grilling (2026-09-10): the PR body is the operator's merge and release reading; it opens with a signed plain-language summary, the answer line, the signed Claim and a per-task proof table, with the record collapsed below; the summary is authored in ultrawrite and quoted verbatim; residuals are a count plus the items the operator can act on.

**Tech Stack:** bash (`fleet/sandbox-boot.sh`, sims through `_sandbox_boot_helpers.mjs`), Node 24 ESM sims, Python 3 (pytest, the boot script's embedded readers), Markdown (`skills/ultrawrite/SKILL.md`)

**Spec:** issue #871's decision table (decisions 8–12); every fact a worker needs is in its task's Context.

**Parallelization rationale:** one wave, two wide. Task 1 teaches ultrawrite the `**Summary:**` block; task 2 rewrites the card the sandbox renders. Task 2 reads the block task 1 teaches, but only its shape (a `**Summary:**` paragraph under the Claim line), which is one literal in both Contexts and is already present in this very plan — so no edge, and the fold of the two is disjoint. No chain.

**Launch base:** after the engine plan (the suite reports; the PR is the gate) has merged, because the card's answer line reads the `## Held` state and the `suite` receipt shape that plan introduces.

## Global Constraints

- The card is written for a person first: nothing above the collapsed record is a hash, a JSON fence, a file listing or a reviewer's sentence.
- Every value on the card is read from the plan file, `report.json`, `gate-receipt.json` or the status page — never narrated by a model at publish time.
- Check: bash -n fleet/sandbox-boot.sh

**Acceptance:** suite — the committed suite is the verification.
