**Context:** *The counter.* `catch_counter.py`'s `derive_catches(run_dir)` builds one `catch-count` row per run directory — `kind`, `runId`, `driverRuns`, `catches`, `reds`, `touched`, `exercises` — and `append_rows` stamps `id`. The run directory holds `status.json` (the boot script copies it into the record beside `events.jsonl`) whose `startedAt` is an ISO string like `2026-09-10T16:28:26Z`; read it with the file's own `_read_json` (a missing, unreadable or malformed file is `None`, never a traceback) and add `startedAt` to the row: the string when present, `null` otherwise. Row identity is unchanged and pinned by `tests/test_ultralearn_catches.py`: `row_id` is the first 16 hex digits of the SHA-256 of `runId + "\n" + "catch-count"`, `runId` being the first `run:open` event's `runId` in `events.jsonl` (`None` without one), and `append_rows` skips a row whose `id` the ledger already holds. So a fixture with three run directories yields three rows only when each `events.jsonl` opens with a `run:open` carrying a distinct `runId` — three directories without one all hash to a single id and append one row. That skip also means a recount of a run already on the ledger is done by first removing that run's old line (or counting into a fresh ledger and merging); the report's last-row-wins rule (M3) covers a ledger that holds two rows for one `runId` however they got there, and the skill says both halves. The existing 29 ledger rows on the laptop carry no `startedAt`; the operator recounts runs 60–89 after this lands. `tests/test_ultralearn_catches.py` (27 cases) pins the counter's rows field by field, including `test_i_row_has_exactly_the_seven_keys` — that case gains the eighth key, and one new case there asserts `startedAt` on a row read from a `status.json`, both under a comment naming this task.

*The report.* `catch_report.py`'s `catch_table(rows, tree_tests)` computes `touchingRuns` as the number of rows whose `touched` intersects the test's union `exercised`. Make it `catch_table(rows, tree_tests, landed=None, runners=None)`: `landed` maps test path → ISO date string; a path absent from `landed` (and every path when `landed` is `None`) lands at the epoch `1970-01-01T00:00:00+00:00`; a row counts toward a test only when the row has a `startedAt` and, parsed as `datetime`, it is strictly later than that test's landing (`Z` is UTC — replace it with `+00:00` before `datetime.fromisoformat`; the git date carries an offset already). A new `landing_dates(tree, paths)` runs `git log --diff-filter=A --format=%cI -1 -- <path>` once per path with `cwd=tree` and maps each path to the printed date, or to the epoch string when git prints nothing or fails (an untracked file, a tree that is not a repository). `_catch_rows` gains a de-duplication pass: rows are keyed by `runId` and the last row in ledger order wins, a row with `runId` `None` kept as its own; `unstamped(rows)` returns the count of those surviving rows with no `startedAt` (`None` or absent). `runners` is a set of test paths: a new `runner_files(tree, paths)` reads each path under `tree` that exists and returns those whose text contains the exact line `# catch-counter: runner` (for a `.mjs` file the line `// catch-counter: runner` also counts); `_status` returns `runner` for a path in `runners` regardless of its catches; `zero_curve` and `zero_over` skip runners; `table_lines` prints them with status `runner`. `main` passes `landing_dates(tree, tree_tests)` and `runner_files(tree, tree_tests)` from `--tree`. The note: `report_lines` appends `<k> row(s) carry no startedAt — recount them` as its last line when `k = unstamped(rows) > 0` — after `curve_lines` without `--n`, after `zero_over_lines` with `--n` — and appends nothing at `k = 0`, so the pins in `tests/test_ultralearn_catch_report.py` on the last line (`test_leg_i_cli_with_n_1_lists_the_one_zero_test` asserts the deletion listing's `tests/test_b.py` is the final line) hold exactly when every fixture row carries `startedAt`. That file (16 cases) builds its rows through `_row(...)` without `startedAt` and pins `touchingRuns` counts against a `tmp_path` tree whose files are untracked, so they land at the epoch: give `_row` a `startedAt` of any real date (`2026-09-01T00:00:00Z`), keep every count, and add nothing else there — `test_t2_leg_c` copies `ROW_A` and inherits it.
