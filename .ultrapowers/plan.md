# The compiler runs every proof line at BASE and says which ones are already green there

**Grammar:** claims-v1

**Claim:** `compile_plan.py --check --base <sha>` executes each task's `Run:` lines in a clean worktree at BASE (the `BASE fact:` machinery already reads the tree there) and prints one line per line that exits 0 (quoted from #1098)
**Summary:** Nearly a quarter of the proof-gate's rejections are exams that already pass before any work lands, so they prove nothing. This plan has the compiler run every proof command against the base commit and say plainly which ones are already green there. You see the hollow proofs on the launch line before a run pays for them, and after one release's count the line becomes a refusal.

**Goal:** Issue #1098, the mechanical half of the second-largest species in #730's harvest (47 of 185 reader rejections, n=185 rejections, harvested 2026-09-16): under `--check --base` the compiler cuts one detached worktree of the plan's repository at BASE, runs every task's Proof `Run:` command there with `ULTRA_BASE` set as the driver sets it, and prints one `GREEN-AT-BASE fact:` line per command that exits 0 — the prover shape for a `Run:` that ends in a clause tag `[Mn]`, the advisory shape for an untagged guard — one line per command killed at 30 s, and one reading line with the total seconds, lines run and lines timed out. This release every one of those lines is a fact under `PLAN OK` (#1084: log before block); the launcher carries them onto the launch line beside the `BASE fact:`, `STALE fact:` and `AUTHORING fact:` lines, and the two authoring references teach the tag.
**Closes:** #1098

**Tech Stack:** Python 3 (`skills/ultrapowers/scripts/compile_plan.py`, pytest under `tests/`), Node ESM (`fleet/launch.mjs`, the launcher sim `fleet/tests/test_launch_compile_facts.mjs` bridged by `tests/test_fleet_suite.py`), the runbook `fleet/RUNBOOK.md`, the authoring references `skills/ultrawrite/SKILL.md` and `skills/ultrapowers/references/plan-markers.md`.

**Spec:** none — issue #1098 is the signed input, restated in each task's Context.

**Parallelization rationale:** one wave of width 3. Task 1 owns the compiler and its new exam; Task 2 owns the two authoring references; Task 3 owns the launcher, the runbook and the launcher sim. The three Files sets are disjoint and no task consumes a symbol another produces: the line prefix `GREEN-AT-BASE fact:` and the tag rule are shared literals pinned in every Context, and Task 3's sim fakes the compiler's stdout exactly as its existing legs do, so it needs nothing Task 1 runs. No chain.

## Global Constraints

- Check: node fleet/tests/test_sims_are_hermetic.mjs | grep -q 'ALL TESTS PASSED'
- Check: git diff --quiet $ULTRA_BASE -- fleet/roles/
- This release a `GREEN-AT-BASE fact:` line is a fact, never a refusal: a compile whose only new output is such lines still prints `PLAN OK` and exits 0, and a plan whose `Run:` lines are all red at BASE compiles byte-identically to BASE's compiler apart from the one reading line.
- A bare `--check` without `--base`, and a plain compile with or without `--base`, run no `Run:` command and print no `GREEN-AT-BASE fact:` line — running a plan's commands is what `--base` asks for, never what a grammar check does.
- Nothing under `fleet/roles/` changes, no new event kind is appended to `events.jsonl`, no new assignment key is added to the VM comment, and no `Check:` line of any plan is executed at BASE — only Proof `Run:` lines are.
- No direct Anthropic API call and no `anthropic` SDK enters any script.
- Findings are about the result — what the compiler prints, what the launch line carries, what the references say — never about the order the work was done in, the number of commits, or whether a test was written before its code.
